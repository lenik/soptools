# ワークフローベースの Playwright テストを実装する

次を読む：

- `web-e2e/workflows.md`
- `sop/TUC.md`（あれば）
- `sop/NTC.md`（あれば）
- `sop/ECS.md`（あれば）

全ワークフローを覆う Playwright テストを実装する。

`sop/` のテスト参照を使い、正例・反用例・エッジシナリオを飛ばさないようにする。

コントロールごとのテストより、ワークフロー志向のテストを優先する。

テストは実ユーザー挙動を鍛えること。

安定したセレクタを使う。

次の順で優先する：

- アクセシブルな role/name
- label（ラベル）
- placeholder（適切な場合）
- 安定した意味的 test ID

次に基づく脆いセレクタを避ける：

- 深い CSS 階層
- nth-child
- 視覚位置
- 生成クラス名

意味的セレクタが足りないときだけ `data-testid` を追加する。

Playwright を楽にするためだけに可視 UI を変えない。
