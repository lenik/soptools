# バックエンド API テストを追加する

自動化されたバックエンド API テストを追加する。

テストは内部実装詳細ではなく、実際の公開 API 挙動を覆うこと。

該当する場合は次を覆う：

- 作成
- 読み取り
- 更新
- 削除／アーカイブ
- 一覧
- 検索
- フィルタ
- ソート
- ページネーション
- ルックアップ
- リレーション
- ツリー操作
- 状態遷移
- 検証失敗
- 未検出
- 競合
- 重複防止
- 一括操作
- 履歴／バージョン挙動
- ドメイン固有操作

次から発見した重要な境界事例もテストする：

- `sop/PRD.md`
- `sop/TUC.md`（あれば）
- `sop/NTC.md`（あれば）
- `sop/ECS.md`（あれば）
- `prisma/schema.prisma`
- `prisma/seed.ts`

ユーザープロンプトや実装作業で新しいケースが明らかになったら、速やかに `sop/TUC.md`、`sop/NTC.md`、`sop/ECS.md` を更新する。
テストは決定的なテストデータを使うこと。

バックエンドテストを実行する。

バックエンドテストスイートが通るまで、バックエンド実装とテストを修正する。

フロントエンド統合の問題をフロントエンド問題とみなす前に、バックエンドテストは通っていること。
