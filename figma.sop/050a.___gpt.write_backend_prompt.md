# Write Codex prompt for backend implementation

Write a complete Codex prompt to create the backend.

Backend stack:

```text
pnpm
Node.js
TypeScript
```

API prefix:

```text
/api/v1/
```

The backend API must cover the useful capabilities of the domain, not only the functions currently used by the web application.

Analyze the nature of each domain object and expose functionality that allows the data to be fully reused by:

- the current web application
- future mobile applications
- other internal systems
- external integrations
- automation
- reporting
- AI agents where appropriate

For every resource, evaluate whether it needs:

```text
CRUD
list
detail
search
lookup
autocomplete
filtering
sorting
pagination
batch retrieval
bulk create/update/delete
relation traversal
tree traversal
state transitions
history
version access
validation
statistics
aggregation
import
export
media operations
external reference resolution
```

Do not mechanically implement all of these for every model.

Implement them when meaningful for the domain.

Backend architecture should separate:

```text
route/controller layer
validation
service/domain logic
data access
shared errors
API serialization
```

Avoid putting domain logic directly in route handlers.

Include robust validation and consistent API errors.

The prompt should instruct Codex to implement the backend against the existing Prisma schema.

Do not require Codex to redesign the product unless an implementation-blocking contradiction is found.
