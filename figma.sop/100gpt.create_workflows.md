# Create complete testing workflows

Based on the complete discussion and the previously produced:

```text
docs/PRD.md
prisma/schema.prisma
prisma/seed.ts
backend design
```

write complete testing-reference workflows as:

```text
web-e2e/workflows.md
```

These workflows are behavioral specifications for Playwright E2E testing.

They are not Playwright code.

The workflows should represent the intended product behavior and should not be rewritten merely to match accidental implementation limitations.

Use readable workflow-style pseudo syntax.

Cover the product with finite but broad functional coverage.

Include:

```text
route access
navigation
create flows
edit flows
delete/archive flows
detail views
search
filter
sort
pagination
tabs
dialogs
sheets
menus
context menus
bulk actions
state transitions
validation failures
cancel paths
empty states
confirmation flows
media interactions
import/export where relevant
cross-entity navigation
important error paths
important boundary cases
```

Do not create artificial branches such as `{correct/error}` unless the underlying business action genuinely has that semantic distinction.

Branches should describe the real condition.

Example:

```text
Login
    enter phone
    enter password

    if password matches:
        submit
        dashboard opens

    if password does not match:
        submit
        login remains open
        error message appears
```

Workflows may contain:

```text
sequence
branch
repeat
selection
precondition
expected visible result
```

but should remain readable and practical rather than formally specified.

Use seed data where it makes workflows reproducible.

Provide download link.
