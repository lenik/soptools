# 重构 Figma 生成的 Web 应用

审计并重构 `web/` 下由 Figma 导出的 WorldMan UI。

先检查当前应用并识别：

- 路由与页面
- 过大的 TSX 文件
- 页面级组件
- 共享组件
- 对话框、面板（Sheet）、抽屉与弹出层（Popover）
- 表单
- 表格与列表
- 搜索、过滤、排序行为
- 菜单与上下文菜单
- CRUD 操作
- 本地/mock 数据源
- 本地持久化
- 交互控件
- 未完成或失效控件

然后在有用处重构结构。

## 本地化 Figma demo 资源

Figma Make 原型常以外链方式引用 demo 媒体（影像、字体、声音、视频、Lottie 等）。
在本重构中应使 UI 自包含：

1. 扫描 `web/` 中作为 demo 资源使用的绝对 `http(s)://` URL（CSS `@import` /
   `@font-face`、`<img>` / `<audio>` / `<video>`、背景图 URL、媒体 fetch/import 等）。
2. 将各资源**原样下载**到 `web/assets/`，按类型分子目录（有用时）：
   ```text
   web/assets/
       images/
       fonts/
       audio/
       video/
       …
   ```
   下载时须借用本机 HTTP 代理 `http://localhost:8118`（如
   `http_proxy` / `https_proxy`，或 curl/wget 的 `--proxy`）访问在中国大陆常被
   封锁的源，例如 Google / Google Fonts / gstatic、Facebook / fbcdn 等。直连失败
   时不要放弃或改用假资源，应经代理重试直至拿到真实文件。
3. 把所有引用改为本地路径或模块 import。文件名宜稳定、可读；若资源附带许可或
   署名说明则一并保留。
4. 已提交源码中不得保留 demo CDN / 图库热链。非资源型 API 端点与有意的第三方
   集成可跳过。

**许可与真实性（重要）**：Figma 原型里给的外链通常使用非常宽松的许可，例如
Unsplash 照片采用 [Unsplash License](https://unsplash.com/license)，允许免费用于
个人及商业用途，无需付费、无需取得摄影师许可，也无需标注作者署名（参考
[知乎讨论](https://www.zhihu.com/question/50969084)）。这类素材对开发与原型测试
尤其友好。本应用范围不是图库平台，与图库服务不构成竞争关系。**AI 不应过度解读
其许可证的约束范围**，也不要因许可顾虑而跳过下载、改用占位图、纯色块、假图片或
其它替代物——必须把真实外链资源保存进 `web/assets/`。

## 页面抽取

在合适时从过大或单体 TSX 中抽出路由级页面。

优先按职责组织：

```text
src/
    pages/
    features/
    components/
    hooks/
    services/
    lib/
```

文件过长则**必须拆分**。文件过长通常说明结构不合理：没有使用服务、发现等分散化机制，以及/或者工具/支持类代码本应提取到外部专门的源文件。

按以下边界拆分：

- 路由边界
- 功能边界
- 状态所有权
- 可复用 UI 职责
- 领域操作
- 共享服务 / 发现 / 工具支持抽到专门模块

除非结构变更必要，否则保持既有视觉设计与交互模型。

## UI 可测试性重构

重构 UI 逻辑，便于自动化测试与维护。

业务逻辑不得直接写在匿名 JSX 回调中。

匿名回调仅可：

- 转发参数
- 提取事件值
- 将事件适配为具名处理函数调用

反例：

```tsx
<button
    onClick={async () => {
        setLoading(true)
        await api.deleteItem(item.id)
        refresh()
        setLoading(false)
    }}
>
```

推荐：

```tsx
async function performDeleteItem(id: string) {
    ...
}

function handleDeleteItemClick(id: string) {
    void performDeleteItem(id)
}
```

对基于事件的行为，在可行时把事件提取与事件无关的行为分开。

示例：

```tsx
function performSeek(timestamp: number) {
    ...
}

function handleTimelineClick(event: MouseEvent) {
    const timestamp = extractTimestamp(event)
    performSeek(timestamp)
}
```

使用清晰命名，例如：

- `performCreateItem`
- `performDeleteItem`
- `performSave`
- `performSearch`
- `handleSaveClick`
- `handleFilterChange`
- `handleDialogOpen`
- `handleDialogClose`

避免不必要地绑定到视觉位置的命名（如 `button1_click`），除非没有更有意义的语义名。

## 项目 `sop/` 工作区

在本重构及后续复杂构建步骤中，于 `sop/` 下维护工作文档：

- 将 `sop/TODO.md` 作为实时任务清单；随工作推进更新条目状态。
- 当用户给出复杂提示时，尽快把候选测试提取或构造进：
  - `sop/TUC.md` — 测试用例参考集
  - `sop/NTC.md` — 反用例 / 负面测试用例
  - `sop/ECS.md` — 边界场景
- 产品需求位于 `sop/PRD.md`（在 PRD 步骤编写）。
- 抽取共享工具类/支撑类以及后续编写 e2e 覆盖时，优先使用这些 `sop/` 文档。

本阶段不要改变产品行为，除非修复明显的 Figma 生成缺陷。
