# 实现基于工作流的 Playwright 测试

阅读：

- `web-e2e/workflows.md`
- `sop/TUC.md`（若存在）
- `sop/NTC.md`（若存在）
- `sop/ECS.md`（若存在）

实现覆盖全部工作流的 Playwright 测试。

使用 `sop/` 测试参考，确保正向用例、反用例与边界场景不被跳过。

优先面向工作流的测试，而不是每个控件一个测试。

测试应锻炼真实用户行为。

使用稳定选择器。

按此顺序优先：

- 可访问的 role/name
- label（标签）
- placeholder（在合适时）
- 稳定语义 test ID

避免基于以下内容的脆弱选择器：

- 深层 CSS 层级
- nth-child
- 视觉位置
- 生成的类名

仅在语义选择器不足时添加 `data-testid`。

不要仅为让 Playwright 更容易而改动可见 UI。
