# Web UI のテーミング（WorldMan styleclass）

プロジェクトのテーマフォーク `sop/themes/` を使い、`web/` にセマンティックな
テーミングを適用する。

本手順は `extend: previous` を宣言する。SOP パスに含まれる場合、
**sopwin はそれを `010` にマージしてグラフ上は単一の手順とする**（プロンプト本文を
連結；表示されるのは `010` ノードのみ）。別ノードを強制するために `extend` を
外さない——WorldMan は安定した手順数を保つ。任意のテーミングはこのマージ拡張であり、
追加の seq ではない。

`sop/themes/` はスイート付属 `suite/worldman/themes/` の**プロジェクトローカルフォーク**
（手順 `000` がシード）。上流の minor-themes アーカイブにプロジェクト時点で依存せず、
本製品向けに進化させる——パレットの追加／改名、HSL 調整、国パックの整理など。

`sop/themes/` が無い場合は、まずスイートパックからコピーする（`scripts/` を含む）。
レイアウト：

```text
sop/themes/
  catalog/          # color-language prose
  minor|vibe|country/  ui|token|web|erp-palettes.mjs
  scripts/generate-theme-css.mjs   # forkable CSS generator
  catalog.tsv
  ELEMENTS.md / SCHEMA.md
```

## 推奨の主要 styleclass 名

WorldMan Web アプリは、共有モジュールの一貫性のため、これらの主要 styleclass /
CSS 変数ステムの使用が**推奨**される。そこからブリッジしたユーティリティ
（`bg-background`、`text-primary`、…）を好む。必要なら拡張／改名してよい——
意図的な逸脱は `sop/TODO.md` に記録する。

| styleclass | 役割 |
|------------|------|
| `background` | アプリ／ページのキャンバス |
| `foreground` | 既定の本文テキスト |
| `primary` | ブランド／主要アクション |
| `primary-foreground` | primary 上のテキスト／アイコン |
| `card` | 浮き上がったサーフェス |
| `card-foreground` | card 上のテキスト |
| `accent` | 選択／柔らかいハイライト |
| `accent-foreground` | accent 上のテキスト |
| `muted-foreground` | 二次／ヒントテキスト |
| `border` | 境界／区切り |
| `ring` | フォーカスリング |
| `destructive` | 危険／削除 |
| `success` | 肯定ステータス |
| `warning` | 注意ステータス |

`:root`（必要なら `.dark`）上で `--${name}` として配線し、CSS フレームワーク
（例：Tailwind `@theme`）経由でブリッジする。共有コントロールは実用的な範囲で
これらのトークンを消費する。

ハードコード色（`bg-blue-500`、`text-gray-900`、`bg-[#007AFF]`、…）をこれらの
役割へ移行する。写真／地図／キャンバスのコントラストが本当に必要な場合のみ、
稀なリテラル色を残す。

## `sop/themes/` から CSS を生成（必須）

パレット HSL を複製するアプリテーマ CSS を手メンテしては**ならない**。同梱
スクリプトでフォークからスタイルシートを生成する（プロジェクトの進化に合わせて
`sop/themes/scripts/` 下でカスタマイズ）：

```bash
# from project root
node sop/themes/scripts/generate-theme-css.mjs
# default out: web/src/styles/themes/themes.css (+ themes-web.css, …)
node sop/themes/scripts/generate-theme-css.mjs --out web/src/styles/themes --sets web,ui
```

生成 CSS を `web/` に import し、`data-theme="<id>"` で切替を駆動する
（catalog.tsv を参照）。パレット編集後はジェネレータを再実行する。

## パレットの読み込み — 意味に応じた全 class set

WorldMan の **web** テーミングは `webPalettes` に**限定されない**。実 UI の意味に
合う class set を使う（ジェネレータ `--sets`）：

| ソース | `web/` で使う場面 |
|--------|------------------------|
| `web-palettes.mjs` | アプリ chrome、ページ、ボタン、ステータス（既定の製品 UI） |
| `ui-palettes.mjs` | 密なツール／IDE 風 chrome（パネル、タブ、サイドバー） |
| `erp-palettes.mjs` | リスト、フォーム、金額、ワークフロー状態 |
| `token-palettes.mjs` | コード／数式／ハイライト面 |

1. `sop/themes/catalog.tsv` を読み、id → `group` + `paletteKey` + catalog md を得る。
2. ブラウザ実行時に `.mjs` を import するより、`scripts/generate-theme-css.mjs` で
   CSS を生成することを好む。
3. `catalog/<Family>.md` を美的ブリーフとして保つ。
4. 共有コンポーネントには上記の推奨 **web** 主要名を好む。他セットは衝突しないよう
   明確な接頭辞（`--ui-*`、`--erp-*`、`--tok-*`）付き CSS 変数へ写す。

プレビュー場面：ローカル静的サーバ経由で `sop/themes/index.html` を開く。

セマンティックな fg/bg ペアはスイートパック内でコントラスト検査済み（≥ 4.5:1）
（`tools/check-theme-contrast.mjs`）。国パックは **zfr L2 + L3** をカバーする。

## 二次／中間トーン

第二の命名体系を発明しては**ならない**。省略時、任意の二次トークンはプライマリから
明度／彩度を調整して**生成**してよい（minor-themes の mid-tones と同精神だが web 役割向け）、
例：`muted`、`secondary`、`popover`、`input-background`、`sidebar*`、`app-canvas`、
およびステータスの `*-foreground` ペア。プロジェクトが mid-tone 合成を必要とするなら
`generate-theme-css.mjs` を拡張する。

## 現在の見た目を `default` として保全する（厳格契約）

テーミングの目的は色を**トークン写像し、任意で切替**することであり、Figma 製品を
再スタイリングすることではない。エージェントはしばしばストックパック（`innocent`、
国パックなど）を初回描画に据えたり、フォントを差し替えたりして失敗する。それを防ぐ：

1. ライブの Figma／エクスポート CSS 色を、リテラル名 `default` のテーマ id へ
   **抽出**する（`current` エイリアスは、同時に `default` も登録する場合のみ）。
   推奨 styleclass トークン（`background`、`foreground`、`primary`、…）へ写す。
   値はエクスポートと一致させなければならない——`default` 構築中にコントラスト、
   色相、グラデーションを「改善」してはならない。
2. **初回描画／起動**は、`localStorage` に前回セッションからの**ユーザー**選択が
   既にある場合を除き、`default` を使わなければならない。生成順が先だからといって
   ストックパックで起動してはならない。
3. `minor`／`vibe`／`country` 下のストックパックは**任意の切替器の選択肢のみ**。
   その CSS 生成はよいが、いずれかを製品デフォルトにしてはならない。意図的に
   非 Figma のデフォルトを出荷する場合は、明示的な製品理由とともに `sop/TODO.md` に
   記録する（稀）。
4. **タイポグラフィはテーミングの範囲外。** パックのブリーフに合わせて
   `font-family`、ウェイト、サイズ尺度、letter-spacing、line-height を変えてはならない。
   インベントリの Typography 節を保ち、色を持つプロパティのみトークンへ書き換える。
5. `sop/theme-default.md` を書き、`default` パックを文書化する：
   - トークン → 抽出値（有用ならソースファイル／セレクタ）
   - 変更していないフォントスタック
   - 起動が `data-theme="default"`（または同等）を使うことの確認

## 適用＋切替器

1. `applyTheme(id)`／任意の `previewTheme(id)` を実装する：
   - `document.documentElement.dataset.theme = id` を設定（生成 CSS と一致）
   - `type === "dark"` のとき `.dark` を切替
   - **明示的なユーザー切替の後にのみ** id を `localStorage` に永続化する
     （ストック id を storage に事前シードしない）
   - 初回描画前に起動時に一度呼ぶ：ユーザー選択が無いとき `default` に解決する
2. Figma chrome を再設計せずにテーマコントロールを追加する：
   - インベントリに既存の設定／オーバーフロー／フッタコントロールがあればそれを好む。
   - なければ控えめな非ヒーロー制御（小さなメニュー項目や開発者向け導線など）。
     エクスポートに無かった目立つヘッダ／ツールバー帯、バッジ群、マーケティング風の
     テーマピッカーを**発明してはならない**。
   - そのコントロール内で任意パックを `minor`／`vibe`／`country`（または catalog 族）で
     グループ化する。`default` を先頭に置き、Figma／製品ルックとしてラベルする。
3. `sop/design-inventory.md` を再確認する——本手順は列挙済みルート／タブを落としてはならず、
   レイアウト、タイポグラフィ、余白、ナビを再スタイリングしてもならない。色のみを
   トークン経由で扱う。
