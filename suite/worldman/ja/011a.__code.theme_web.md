# Web UI のテーミング（WorldMan styleclass）

プロジェクトのテーマフォーク `sop/themes/` を使い、`web/` にセマンティックな
テーミングを適用する。

本手順は `extend: previous` を宣言する。SOP パスに含まれる場合、
**sopwin はそれを `010` にマージしてグラフ上は単一の手順とする**（プロンプト本文を
連結；表示されるのは `010` ノードのみ）。別ノードを強制するために `extend` を
外さない——WorldMan は安定した手順数を保つ。任意のテーミングはこのマージ拡張であり、
追加の seq ではない。

`sop/themes/` はスイート付属 `suite/worldman/themes/` の**プロジェクトローカルフォーク**
（手順 `000` がシード）。上流の minor-themes アーカイブにプロジェクト時点で依存せず、
本製品向けに進化させる——パレットの追加／改名、HSL 調整、国パックの整理など。

`sop/themes/` が無い場合は、まずスイートパックからコピーする（`scripts/` を含む）。
レイアウト：

```text
sop/themes/
  catalog/          # color-language prose
  minor|vibe|country/  ui|token|web|erp-palettes.mjs
  scripts/generate-theme-css.mjs   # forkable CSS generator
  catalog.tsv
  ELEMENTS.md / SCHEMA.md
```

## 推奨の主要 styleclass 名

WorldMan Web アプリは、共有モジュールの一貫性のため、これらの主要 styleclass /
CSS 変数ステムの使用が**推奨**される。そこからブリッジしたユーティリティ
（`bg-background`、`text-primary`、…）を好む。必要なら拡張／改名してよい——
意図的な逸脱は `sop/TODO.md` に記録する。

| styleclass | 役割 |
|------------|------|
| `background` | アプリ／ページのキャンバス |
| `foreground` | 既定の本文テキスト |
| `primary` | ブランド／主要アクション |
| `primary-foreground` | primary 上のテキスト／アイコン |
| `card` | 浮き上がったサーフェス |
| `card-foreground` | card 上のテキスト |
| `accent` | 選択／柔らかいハイライト |
| `accent-foreground` | accent 上のテキスト |
| `muted-foreground` | 二次／ヒントテキスト |
| `border` | 境界／区切り |
| `ring` | フォーカスリング |
| `destructive` | 危険／削除 |
| `success` | 肯定ステータス |
| `warning` | 注意ステータス |

`:root`（必要なら `.dark`）に `--${name}` として配線し、CSS フレームワーク
（例：Tailwind `@theme`）経由でブリッジする。共有コントロールは実用的なら
これらのトークンを消費する。

ハードコード色（`bg-blue-500`、`text-gray-900`、`bg-[#007AFF]`、…）を
これらの役割へ移行する。写真／地図／キャンバスのコントラストが本当に
必要な場合のみ、稀なリテラル色を残す。

## `sop/themes/` から CSS を生成（必須）

パレット HSL を複製するアプリテーマ CSS を手メンテしては**ならない**。
同梱スクリプトでフォークからスタイルシートを生成する（プロジェクト進化に合わせ
`sop/themes/scripts/` 下をカスタム）：

```bash
# from project root
node sop/themes/scripts/generate-theme-css.mjs
# default out: web/src/styles/themes/themes.css (+ themes-web.css, …)
node sop/themes/scripts/generate-theme-css.mjs --out web/src/styles/themes --sets web,ui
```

生成 CSS を `web/` で import し、`data-theme="<id>"` で切り替えを駆動する
（catalog.tsv 参照）。パレット編集後はジェネレータを再実行する。

## パレット読み込み — セマンティクスに応じた全クラスセット

WorldMan の **web** テーミングは `webPalettes` に**限定されない**。実際の UI 意味に
合うクラスセットを使う（ジェネレータ `--sets`）：

| ソース | `web/` で使うとき |
|--------|------------------------|
| `web-palettes.mjs` | アプリ chrome、ページ、ボタン、ステータス（既定の製品 UI） |
| `ui-palettes.mjs` | 密なツール／IDE 風 chrome（パネル、タブ、サイドバー） |
| `erp-palettes.mjs` | リスト、フォーム、金額、ワークフローステータス |
| `token-palettes.mjs` | コード／式／ハイライトサーフェス |

1. `sop/themes/catalog.tsv` を読み、id → `group` + `paletteKey` + catalog md を把握する。
2. ブラウザ実行時に `.mjs` を import するより、`scripts/generate-theme-css.mjs` 経由の
   CSS 生成を好む。
3. `catalog/<Family>.md` を美的ブリーフとして保つ。
4. 共有コンポーネントには上記の推奨 **web** 主要名を好み；他セットは衝突しないよう
   明確な接頭辞（`--ui-*`、`--erp-*`、`--tok-*`）付き CSS 変数へ写す。

プレビューシーン：ローカル静的サーバで `sop/themes/index.html` を開く。

セマンティックな fg/bg ペアはスイートパックでコントラスト検査済み（≥ 4.5:1）
（`tools/check-theme-contrast.mjs`）。国パックは **zfr L2 + L3** をカバーする。

## セカンダリ／中間トーン

第二の命名スキームを**発明しない**。任意のセカンダリトークンは省略時に
**生成**してよい——プライマリから明度／彩度を調整（minor-themes の mid-tones と同じ
職人精神だが web 役割向け）、例：`muted`、`secondary`、`popover`、
`input-background`、`sidebar*`、`app-canvas`、およびステータスの
`*-foreground` ペア。プロジェクトが中間トーン合成を必要なら
`generate-theme-css.mjs` を拡張する。

## 現在の見た目をデフォルトとして保全

テーマを配線するとき、**プロジェクト既存の Figma／CSS 色をデフォルトとして保つ**。
まずそれらの生きた色を WorldMan styleclass トークンへ写す（エクスポートに合う
`default` / `current` パックまたは起動時の値）。

テーミングが入ったからといって、UI をストックの `innocent`（や他パック）で
黙って置き換えては**ならない**。`minor` / `vibe` / `country` 下のストックパックは
**任意の切り替え選択肢**であり、初回ペイントは現在の製品に見えるべきである。

## 適用 + スイッチャー

1. `applyTheme(id)` / 任意の `previewTheme(id)` を実装する：
   - `document.documentElement.dataset.theme = id` を設定（生成 CSS と一致）
   - `type === "dark"` のとき `.dark` をトグル
   - id を `localStorage` に永続化
   - 実用的なら初回ペイント前の起動時に一度呼ぶ
2. Figma chrome を再デザインせずにテーマコントロールを追加する：
   - インベントリに既にある設定／オーバーフロー／フッタ制御を好む。
   - 無ければ控えめな非ヒーロー制御（例：小さなメニュー項目や開発者用アフォーダンス）。
     エクスポートに無かった目立つヘッダ／ツールバー帯、バッジ群、マーケティング風
     テーマピッカーを**発明しない**。
   - その制御内で任意パックを `minor` / `vibe` / `country`（または catalog ファミリー）
     でグループ化する。
3. デフォルト＝**現在の製品色**（上記参照）。意図的なストックパック既定は
   `sop/TODO.md` に記す。

レイアウト、タイポグラフィ、余白、操作を保全する。テーミングはトークン経由で
色だけを変える。`sop/design-inventory.md` を再確認する——本手順は列挙済み
ルート／タブを落としたり再スタイリングしたりしてはならない。

## SOP 駆動コミット

本ファイルは `010` にマージされるため、マージ実行でのコミットは `[sop010]` を使う
（グラフ上の活性ステップ id は1つ）。**作業が進むにつれて**——まとまったスライスのあと——
コミットし、末尾に一度だけ、ではない。`CHECKPOINT.md` を参照。
