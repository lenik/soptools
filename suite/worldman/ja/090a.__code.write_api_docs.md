# 最終 API 文書の作成

バックエンド実装と統合が安定したら、完全な `docs/api.md` を書く。

この文書は実際に実装された API を記述する。

as-built API 契約である。

文書化する：

- API ベースパス
- 共通規約
- 該当する場合の認証
- リクエスト形式
- レスポンス形式
- エラー形式
- ページネーション
- フィルタリング
- ソート
- 検索
- 一括操作の規約
- リソースエンドポイント
- 状態遷移エンドポイント
- 関係エンドポイント
- ドメイン固有エンドポイント
- 例
- 重要な検証ルール
- 重要な衝突挙動

各エンドポイントについて、バックエンドソースを読まずに別アプリが API を使えるだけの
情報を含める。

存在しないエンドポイントを文書化しない。

現在の Web アプリが呼ばないという理由だけで、有用な実装済みエンドポイントを省略しない。

## SOP 駆動コミット

本手順が**進むにつれて**コミットする——まとまったスライスのあと（成果物の書き出し、
1ルート／機能の抽出、1モック置換、一部テストが green、…）。
手順全体を末尾の単一コミットに**先送りしない**。

SOP 駆動の件名は `[sop090]` で始めなければならない。本 SOP パックの
`CHECKPOINT.md` を参照。
