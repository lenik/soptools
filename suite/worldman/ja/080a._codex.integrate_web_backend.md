# Web とバックエンドを統合する

`web/` を `backend/` につなぎ、UI が実 API を使うようにする。

## 目標

- 適切な箇所でデモ／mock／ローカル専用データ源をバックエンド API に置き換える。
- 承認済みの UI 構造と見た目を保つ。統合中だからといってアプリを再設計しない。
- 明確なフロントエンド API／サービス層を作る（優先：`web/src/services/` または同等のクライアント）。ページコンポーネントへ生の `fetch()` を散らさない。

## UI の挙動

次を正しく扱うこと：

- 読み込み中
- 空状態
- サーバーエラー
- 検証エラー
- 未検出
- 競合
- 保存成功
- 削除／アーカイブ確認
- 更新（リフレッシュ）
- 再読み込み後の永続化
- 検索
- フィルタ
- ソート
- ページネーション

大きく再利用されるデータセットでは、ドメインに合うならサーバー側の処理を優先する。

## 統合がバックエンドの問題を露出したとき

本当の設計問題ならバックエンドを必要に応じてリファクタする。挙動が変わる場合：

- バックエンドテストを更新する
- 公開 API の一貫性を保つ
- バックエンドテストを再実行する
