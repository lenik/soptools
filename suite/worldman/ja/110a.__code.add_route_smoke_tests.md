# Playwright ルート smoke テストの追加

`web-e2e/` 下に Playwright E2E テストを追加する。

まずルート smoke カバレッジを実装する。

ルーター**および** `sop/design-inventory.md` からアプリのルート表を列挙する。
ステータス `kept` または `moved` のすべてのインベントリルートは、インベントリが
理由付きで `dropped` とマークしない限り、smoke テストを持たなければならない。

到達可能な各アプリルートについて：

- ルートを開く
- ページが描画されることを検証する
- クラッシュしないことを検証する
- 致命的なページエラーがないことを検証する
- 予期しない未捕捉例外がないことを検証する
- ページが空白でないことを検証する
- インベントリがそのルートにタブを列挙している場合、それらのタブがまだ
  マウントされることをスポットチェックする（クリックまたはディープリンク）——
  黙って消えていないこと

動的ルートは、有効なシードデータ ID を使うか、必要なテストデータを作成する。

ルート smoke テストを十分な機能カバレッジと見なさない。

## SOP 駆動コミット

本手順が**進むにつれて**コミットする——まとまったスライスのあと（成果物の書き出し、
1ルート／機能の抽出、1モック置換、一部テストが green、…）。
手順全体を末尾の単一コミットに**先送りしない**。

SOP 駆動の件名は `[sop110]` で始めなければならない。本 SOP パックの
`CHECKPOINT.md` を参照。
