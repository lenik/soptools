# バックエンドを実装する

`sop/Backend implementation prompt.md` を読み、`backend/` 配下にバックエンドを実装する。

## Prisma パッケージ

まず既存の `prisma/` ディレクトリを確認する。少なくとも次を想定する：

- `prisma/schema.prisma`
- `prisma/seed.ts`（作成済みなら）
- `prisma/package.json`（無ければ追加）

このパッケージを使う。別の Prisma ルートを新設しない。

## 修正マージ

シードが既存のバックエンド設計プロンプトや既存 `backend/` に対する不足を見つけた
場合、修正リクエストが残っていることがある:

- `prisma/request-for-refactor.md` — スキーマ変更
- `sop/Backend amends.md` — それらに伴うバックエンド／API 変更

実装の**前または並行して**マージする。不足が分かっている schema/API のまま作らない。

### スキーマ修正をマージする

`prisma/request-for-refactor.md` がある場合:

1. 各 issue を読む。
2. **blocking** を `prisma/schema.prisma` へ適用（必要なら `comments.sql` 等も）。
3. **recommended** は小さく可逆で一貫 API に必要なものだけ適用し、他は実装ノートに延期。
4. 改訂後 schema に合うよう `prisma/seed.ts` を更新。
5. 完了したら `prisma/request-for-refactor.md` を**削除**。

### バックエンド修正をマージする

`sop/Backend amends.md` がある場合:

1. 各 API／振る舞い変更を読む。
2. `backend/` 実装へ取り込み、マージ済み schema/seed と整合させる。
3. `sop/Backend implementation prompt.md` と衝突したら seed/schema 側を優先。
4. 完了したら `sop/Backend amends.md` を**削除**。

リポジトリが pnpm でインストール・実行できることを確認する。
