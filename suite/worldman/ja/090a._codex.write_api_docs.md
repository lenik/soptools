# 最終 API ドキュメントを書く

バックエンド実装と統合が安定したら、完全な `docs/api.md` を書く。

この文書は実際に実装された API を記述する。

as-built の API 契約である。

文書化する内容：

- API ベースパス
- 共通規約
- 認証（該当時）
- リクエスト形式
- レスポンス形式
- エラー形式
- ページネーション
- フィルタ
- ソート
- 検索
- 一括操作の規約
- リソースエンドポイント
- 状態遷移エンドポイント
- リレーションエンドポイント
- ドメイン固有エンドポイント
- 例
- 重要な検証ルール
- 重要な競合挙動

各エンドポイントは、別アプリがバックエンド源コードを読まずに API を使えるだけの情報を含める。

存在しないエンドポイントを文書化しない。

現行 Web アプリが呼んでいないという理由だけで、有用な実装済みエンドポイントを省略しない。
