# Web UI をテーマ化する（WorldMan styleclass）

プロジェクトのテーマ fork `sop/themes/` を使い、`web/` にセマンティックな
テーマを適用する。本手順は `010` を延長する（`extend: previous`）。

`sop/themes/` はスイート添付 `suite/worldman/themes/` の**プロジェクトローカル
fork**（手順 `000` で投入）。この製品向けに色板の追加・HSL 調整・国パック整理
をしてよい。プロジェクト時点で upstream の minor-themes に**依存しない**。

`sop/themes/` が無い場合は、先にスイートからコピー（`scripts/` 含む）：

```text
sop/themes/
  catalog/          # 色彩言語の散文
  minor|vibe|country/  ui|token|web|erp-palettes.mjs
  scripts/generate-theme-css.mjs   # カスタム可能な CSS 生成スクリプト
  catalog.tsv
  ELEMENTS.md / SCHEMA.md
```

## 推奨の主 styleclass 名

WorldMan Web アプリは次の主 styleclass / CSS 変数語幹の使用を**推奨**する
（共有モジュールの一貫性のため）。`bg-background` 等のユーティリティへ橋渡し
する。必要なら拡張・改名可。意図的な逸脱は `sop/TODO.md` に記す。

| styleclass | 役割 |
|------------|------|
| `background` | アプリ／ページのキャンバス |
| `foreground` | 既定の本文 |
| `primary` | ブランド／主アクション |
| `primary-foreground` | primary 上の文字／アイコン |
| `card` | 浮いた面 |
| `card-foreground` | カード上の文字 |
| `accent` | 選択／柔らかいハイライト |
| `accent-foreground` | accent 上の文字 |
| `muted-foreground` | 副次／ヒント文字 |
| `border` | 枠線／区切り |
| `ring` | フォーカスリング |
| `destructive` | 危険／削除 |
| `success` | 成功ステータス |
| `warning` | 警告ステータス |

`:root`（必要なら `.dark`）に `--${name}` として書き、フレームワークへ橋渡し。
共有コントロールは可能な限りこれらのトークンを消費する。ハードコード色を上記
役割へ移行。

## `sop/themes/` から CSS を生成する（必須）

アプリ CSS にパレット HSL を**手メンテで複製しない**。同梱スクリプトで fork
からスタイルシートを生成する（`sop/themes/scripts/` でカスタム可）：

```bash
# プロジェクトルートから
node sop/themes/scripts/generate-theme-css.mjs
# 既定出力: web/src/styles/themes/themes.css（および themes-web.css など）
node sop/themes/scripts/generate-theme-css.mjs --out web/src/styles/themes --sets web,ui
```

生成 CSS を `web/` で import し、`data-theme="<id>"` で切替（catalog.tsv）。
パレット変更後は再生成する。

## 意味に応じて全 class セットを使う

WorldMan の **web** テーマ化は `webPalettes` に**限定しない**。実 UI の意味に合う
セットを選ぶ（生成器 `--sets`）：

| ソース | `web/` での用途 |
|--------|----------------|
| `web-palettes.mjs` | アプリクロム、ページ、ボタン、状態（既定の製品 UI） |
| `ui-palettes.mjs` | 密なツール／IDE 風クロム（パネル、タブ、サイドバー） |
| `erp-palettes.mjs` | 一覧、フォーム、金額、ワークフロー状態 |
| `token-palettes.mjs` | コード／式／ハイライト面 |

1. `sop/themes/catalog.tsv` で id → `group` + `paletteKey` + catalog md。
2. ブラウザで `.mjs` を直接 import するより、`scripts/generate-theme-css.mjs`
   で CSS 生成を優先。
3. `catalog/<Family>.md` を美的ブリーフとして残す。
4. 共有コンポーネントは上記**推奨** web 主名を優先；他セットは
   `--ui-*` / `--erp-*` / `--tok-*` 接頭辞で衝突を避ける。

4 シーンのプレビュー: ローカル静的サーバで `sop/themes/index.html` を開く。

意味的前景／背景は ≥ 4.5:1。国パレットは **zfr L2 + L3** をカバー。

## 副次／中間色

並行命名を作らない。欠けた副次トークンは主色から明度／彩度を調整して生成してよい
（`muted`、`secondary`、`popover`、`sidebar*`、`app-canvas` など）。中間色合成が
必要なら `generate-theme-css.mjs` を拡張する。

## 現行配色を既定として残す

テーマ導入時は、**プロジェクト既存の Figma / CSS 配色を既定として保つ**。
まず現行色を WorldMan styleclass トークンへ写す（`default` / `current` パック、
またはエクスポートと一致する起動値）。

テーマ機構が入ったからといって、在庫の `innocent`（や他パック）へ**黙って
置き換えない**。`minor` / `vibe` / `country` の在庫は**任意の切替候補**；
初回描画は現行プロダクトの見た目のまま。

## 適用とスイッチャー

1. `applyTheme(id)`／任意 `previewTheme(id)`：
   - `document.documentElement.dataset.theme = id`（生成 CSS と対応）
   - `type === "dark"` なら `.dark`
   - `localStorage`；可能なら初回描画前
2. クロムに**見える**テーマ操作を置き、`minor` / `vibe` / `country` でグループ化。
3. 既定 = **現行プロダクト配色**（上記）。在庫パックを故意に既定にする場合は
   `sop/TODO.md` に記す。

レイアウトと操作は維持し、色だけをトークン経由で変える。
