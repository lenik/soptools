# インタラクティブコントロールカバレッジの監査

ワークフローテスト実装後、すべてのインタラクティブ GUI コントロールを監査する。

存在すれば `sop/TUC.md`、`sop/NTC.md`、`sop/ECS.md` と照合し、既知シナリオに
コントロール経路が残っていないことがないようにする。

意味のあるインタラクティブコントロールすべてが、少なくとも1つの E2E テストで
演習されることを保証する。

該当する場合、含める：

- buttons
- links
- tabs
- menus
- context menus
- dropdowns
- selects
- search inputs
- filters
- sorting controls
- pagination
- checkboxes
- radio buttons
- switches
- forms
- dialogs
- sheets
- drawers
- date/time controls
- file uploads
- downloads
- media controls
- drag/drop
- expand/collapse controls
- bulk-selection controls
- destructive confirmations

既存ワークフローが既にそのコントロールをカバーしているとき、冗長なテストを作らない。

目標は操作カバレッジであり、テスト件数の水増しではない。

`sop/design-inventory.md` に列挙されたタブやその他 chrome と照合し、
インベントリサーフェスに少なくとも1つの操作経路が残っていないことがないようにする。

## SOP 駆動コミット

本手順が**進むにつれて**コミットする——まとまったスライスのあと（成果物の書き出し、
1ルート／機能の抽出、1モック置換、一部テストが green、…）。
手順全体を末尾の単一コミットに**先送りしない**。

SOP 駆動の件名は `[sop130]` で始めなければならない。本 SOP パックの
`CHECKPOINT.md` を参照。
