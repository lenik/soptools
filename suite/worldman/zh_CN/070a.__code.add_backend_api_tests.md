# 添加后端 API 测试

添加自动化后端 API 测试。

测试应覆盖实际公共 API 行为，而非内部实现细节。

在适用处覆盖：

- create
- read
- update
- delete/archive
- list
- search
- filter
- sort
- pagination
- lookup
- relations
- tree operations
- state transitions
- validation failures
- not found
- conflicts
- duplicate prevention
- bulk operations
- history/version behavior
- domain-specific operations

亦测试从以下材料发现的重要边界情况：

- `sop/PRD.md`
- `sop/TUC.md`（若存在）
- `sop/NTC.md`（若存在）
- `sop/ECS.md`（若存在）
- `prisma/schema.prisma`
- `prisma/seed.ts`

当用户提示或实现工作揭示新情况时，及时更新 `sop/TUC.md`、`sop/NTC.md` 与 `sop/ECS.md`。
测试应使用确定的测试数据。

运行后端测试。

修复后端实现与测试，直至后端测试套件通过。

在把前端集成问题当作前端问题之前，后端测试必须通过。

## SOP 驱动的提交

**随本步骤演进**提交——在每个连贯切片之后（写出产物、
抽出一条路由/功能、替换一个 mock、子集测试转绿，…）。
**不要**把整个步骤拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop070]` 开头。见本 SOP 包中的
`CHECKPOINT.md`。
