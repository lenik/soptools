# 添加后端 API 测试

添加自动化后端 API 测试。

测试应覆盖真实公共 API 行为，而不是内部实现细节。

在适用处覆盖：

- create
- read
- update
- delete/archive
- list
- search
- filter
- sort
- pagination
- lookup
- relations
- tree operations
- state transitions
- validation failures
- not found
- conflicts
- duplicate prevention
- bulk operations
- history/version behavior
- domain-specific operations

同时测试从下列来源发现的重要边界情况：

- `sop/PRD.md`
- `sop/TUC.md`（若存在）
- `sop/NTC.md`（若存在）
- `sop/ECS.md`（若存在）
- `prisma/schema.prisma`
- `prisma/seed.ts`

用户提示或实现工作暴露新用例时，尽快更新 `sop/TUC.md`、`sop/NTC.md`、`sop/ECS.md`。
测试应使用确定的测试数据。

运行后端测试。

修复后端实现与测试，直到后端测试套件通过。

在把前端集成问题当成前端问题之前，后端测试必须先通过。

## SOP 驱动的提交

**随本步骤演进**提交——每完成一块连贯切片（产物已写出、某条路由/功能已抽出、某个 mock 已替换、某子集测试已绿等）。**不要**把整步工作拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop070]` 开头。见本 SOP 包中的 `CHECKPOINT.md`。
