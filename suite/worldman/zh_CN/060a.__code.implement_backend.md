# 实现后端

读取 `sop/Backend implementation prompt.md` 并在 `backend/` 下实现后端。

## Prisma 包

先检查已有 `prisma/` 目录，至少应有：

- `prisma/schema.prisma`
- `prisma/seed.ts`（若已编写）
- `prisma/package.json`（若缺失则补上）

使用该包，不要另起一套 Prisma 根目录。

## 修订合并

Seed 若相对已有后端设计提示词或已有 `backend/` 发现缺口，可能留下修订请求：

- `prisma/request-for-refactor.md` — schema 变更
- `sop/Backend amends.md` — 由这些发现引出的后端/API 变更

在实现时**先合并或边实现边合并**；不要对着已知不足的 schema/API 硬写后端。

### 合并 schema 修订

若存在 `prisma/request-for-refactor.md`：

1. 阅读其中每一项问题。
2. 将 **blocking** 项应用到 `prisma/schema.prisma`（必要时同步 `comments.sql` 等）。
3. 对 **recommended** 项：若改动小、可回退且为一致 API 所必需则一并应用；否则仅在实现说明中记录延期。
4. 更新 `prisma/seed.ts`，使其与修订后的 schema 一致。
5. 完成后**删除** `prisma/request-for-refactor.md`。

### 合并后端修订

若存在 `sop/Backend amends.md`：

1. 阅读每一项 API/行为变更请求。
2. 合入 `backend/` 实现，并与已合并的 schema/seed 保持一致。
3. 若与 `sop/Backend implementation prompt.md` 冲突，以 seed/schema 压力为准。
4. 完成后**删除** `sop/Backend amends.md`。

## 后端

确保仓库可用 pnpm 安装并运行。

在 `/api/v1/` 前缀下实现后端 API。
