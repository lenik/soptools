## 来源优先级

判定预期行为时，优先：

1. `sop/PRD.md`
2. 存在时的 `sop/TUC.md` / `sop/NTC.md` / `sop/ECS.md`
3. `schema.prisma` 中的明确领域规则
4. 稳定的后端/API 行为
5. 已实现的用户可见行为
6. seed 场景与 fixtures
7. 孤立 UI 产物或死掉的导出/脚手架控件

不要仅为迁就明显实现缺陷而改写预期工作流。

不要为不受支持的产品功能发明工作流。

若重要行为未解决，在相关工作流或最终未解决章节中加入简短 **未解决行为** 说明，而不是捏造规则。

## 工作流目标

这些工作流是 Playwright 的行为验收规格。

它们不是 Playwright 源码。

使用可读的工作流式伪代码。

以有限但广泛的功能覆盖产品。

在适用处包含：

- 路由访问
- 导航
- 创建流程
- 编辑流程
- 删除/归档流程
- 详情视图
- 搜索
- 过滤
- 排序
- 分页
- 标签页
- 对话框
- 面板（Sheet）
- 菜单
- 上下文菜单
- 批量操作
- 状态转换
- 校验失败
- 取消路径
- 空状态
- 确认流程
- 媒体交互
- 导入/导出
- 跨实体导航
- 重要错误路径
- 重要边界情况

优先现实端到端工作流，而不是每个按钮一个工作流。

在能使场景确定可复现处使用 seed 数据。

## 分支语法

分支应描述真实条件。

避免通用分支如 `{correct/error}`，除非这些术语在领域中确实有意义。

优先：

```text
Login
    enter phone
    enter password

    if password matches:
        submit
        dashboard opens

    if password does not match:
        submit
        login remains open
        error message appears
```

工作流可使用：

- 前置条件
- 顺序
- 选择
- 分支
- 重复
- 预期可见结果

保持实用、可读，并可直接在 Playwright 中实现。

将完成产物直接写入 `web-e2e/workflows.md`。
