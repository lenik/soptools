# 最终覆盖审计

对以下材料做最终产品覆盖审计：

- `sop/PRD.md`
- `sop/design-inventory.md`
- `sop/seed-coverage.md`
- `sop/TUC.md`（若存在）
- `sop/NTC.md`（若存在）
- `sop/ECS.md`（若存在）
- `sop/TODO.md`（若存在）

- `backend/`
- `docs/api.md`
- `web/`
- `web-e2e/workflows.md`

检查：

- 无实现的 PRD 功能
- 标记为 `kept`/`moved` 却相对 Figma 基线缺失、空白或被掏空的 design-inventory 路由/页签
- design-inventory **Typography** 族被换成不同字体或主题包字体
- 启动主题不是 `default`（Figma 提取），或库存包被静默做成产品默认（若跑过 `011`，见 `sop/theme-default.md`）
- 仍使空用户可见列表/表格的 seed-coverage 缺口
- 非 `matched` 行缺少 seed-coverage **Discrepancy log**，或 media↔text `mismatched` 无理由
- 无后端或 E2E 覆盖的 TUC / NTC / ECS 用例
- 本应已关闭的未决 `sop/TODO.md` 条目
- 已实现却缺失文档的领域功能
- 无真实行为的 UI 控件
- 死按钮
- 死菜单
- 死路由
- 在 seed 对等**之后**本应已被替换的过时 mock 数据
- 过时本地持久化
- 无后端测试的 API 端点
- 无 E2E 路径的重要后端功能
- 无 Playwright 覆盖的工作流步骤
- 无覆盖的交互控件
- 陈旧 API 文档
- 本应由后端处理却从未处理的 schema 字段
- 与后端行为不一致的前端假设
- 改写了许多表面却无中间 `[sopNNN]` 提交的 SOP 工作（记在 `sop/TODO.md`；不要改写已发布历史）

修复真实缺口——偏好恢复清单支持的 UI/seed 数据（以及
Figma `default` 主题 / 字体栈），而不是删除表面或“重样式”
好让审计“通过”。

若 API 有意超出当前 web 应用可复用，不要强迫每个后端 API 能力都有 GUI。

最后运行：

- 后端测试
- web 构建/类型检查
- Playwright E2E 测试

所有必需测试必须通过。

抽出一条路由/功能、替换一个 mock、子集测试转绿，…）。
**不要**把整个步骤拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop150]` 开头。见本 SOP 包中的
`CHECKPOINT.md`。
