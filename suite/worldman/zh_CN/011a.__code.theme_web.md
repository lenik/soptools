# 为 web UI 做主题化（WorldMan styleclass）

使用项目主题 fork `sop/themes/`，为 `web/` 做语义化主题化。

本步骤声明 `extend: previous`。纳入 SOP 路径时，**sopwin 会把它并入 `010`，图上仍是一步**（提示词正文拼接；只显示 `010` 节点）。不要去掉 `extend` 去强制独立节点——WorldMan 保持稳定的步骤数；可选主题化是这种合并扩展，而不是额外的 seq。

`sop/themes/` 是 suite 附件 `suite/worldman/themes/` 的**项目本地 fork**（由步骤 `000` 播种）。为本产品演进它——增删色板、调整 HSL、裁剪国家包——而不在项目期依赖上游 minor-themes 归档。

若缺少 `sop/themes/`，先从 suite 包拷贝（含 `scripts/`）。布局：

```text
sop/themes/
  catalog/          # color-language prose
  minor|vibe|country/  ui|token|web|erp-palettes.mjs
  scripts/generate-theme-css.mjs   # forkable CSS generator
  catalog.tsv
  ELEMENTS.md / SCHEMA.md
```

## 推荐的主 styleclass 名称

WorldMan web 应用**推荐**使用这些主 styleclass / CSS 变量词干，以便共享模块保持一致。优先使用从它们桥接的工具类（`bg-background`、`text-primary` 等）。项目可按需扩展或重命名——有意偏离请记在 `sop/TODO.md`。

| styleclass | 职责 |
|------------|------|
| `background` | 应用 / 页面画布 |
| `foreground` | 默认正文文字 |
| `primary` | 品牌 / 主操作 |
| `primary-foreground` | 主色上的文字/图标 |
| `card` | 浮起的卡片表面 |
| `card-foreground` | 卡片上的文字 |
| `accent` | 选中 / 柔和高亮 |
| `accent-foreground` | accent 上的文字 |
| `muted-foreground` | 次要 / 提示文字 |
| `border` | 边框 / 分隔 |
| `ring` | 焦点环 |
| `destructive` | 危险 / 删除 |
| `success` | 积极状态 |
| `warning` | 警示状态 |

在 `:root`（以及需要时的 `.dark`）上以 `--${name}` 接线，并经 CSS 框架桥接（如 Tailwind `@theme`）。共享控件在可行时应消费这些 token。

把硬编码颜色（`bg-blue-500`、`text-gray-900`、`bg-[#007AFF]` 等）迁到这些角色。仅在照片/地图/画布对比真正需要时，保留稀有字面颜色。

## 从 `sop/themes/` 生成 CSS（必需）

**不要**手工维护与色板 HSL 重复的应用主题 CSS。用随附脚本从 fork 生成样式表（随项目演进在 `sop/themes/scripts/` 下定制）：

```bash
# from project root
node sop/themes/scripts/generate-theme-css.mjs
# default out: web/src/styles/themes/themes.css (+ themes-web.css, …)
node sop/themes/scripts/generate-theme-css.mjs --out web/src/styles/themes --sets web,ui
```

在 `web/` 中导入生成的 CSS，并用 `data-theme="<id>"` 驱动切换（见 catalog.tsv）。色板改动后重新跑生成器。

## 加载色板 — 按语义选用全部 class set

WorldMan **web** 主题化**不**限于 `webPalettes`。按真实 UI 含义选用 class set（生成器 `--sets`）：

| 来源 | 在 `web/` 中何时使用 |
|------|----------------------|
| `web-palettes.mjs` | 应用外壳、页面、按钮、状态（默认产品 UI） |
| `ui-palettes.mjs` | 偏工具型、信息密度高的 / IDE 式界面外壳（面板、页签、侧栏） |
| `erp-palettes.mjs` | 列表、表单、金额、工作流状态 |
| `token-palettes.mjs` | 代码 / 公式 / 高亮表面 |

1. 读 `sop/themes/catalog.tsv`，得到 id → `group` + `paletteKey` + catalog md。
2. 优先经 `scripts/generate-theme-css.mjs` 生成 CSS，不要在浏览器运行时导入 `.mjs`。
3. 把 `catalog/<Family>.md` 当作风格说明保留。
4. 共享组件优先用上文推荐的 **web** 主名；其它 set 映射到带清晰前缀的 CSS 变量（`--ui-*`、`--erp-*`、`--tok-*`），以免冲突。

预览场景：用本地静态服务器打开 `sop/themes/index.html`。

语义 fg/bg 对在 suite 包里做过对比度检查（≥ 4.5:1）（`tools/check-theme-contrast.mjs`）。国家包覆盖 **zfr L2 + L3**。

## 次级 / 中间调

**不要**发明第二套命名方案。省略时，可选次级 token 可由**生成**得到——从主色调整明度/饱和度（与 minor-themes 中间调同样的做法，但面向 web 角色），例如 `muted`、`secondary`、`popover`、`input-background`、`sidebar*`、`app-canvas`，以及状态 `*-foreground` 对。若项目需要中间调合成，扩展 `generate-theme-css.mjs`。

## 把当前外观保留为 `default`（硬性约定）

主题化的目的，是把颜色映射成 token，并在需要时提供切换——而不是拿主题去重做 Figma 产品的样式。执行时常见失误：把现成色板（如 `innocent`、某国家包）直接当成首屏默认主题，或顺手改掉字体。务必避免：

1. **提取**当前 Figma / 导出 CSS 中的实际颜色，做成主题 id 为 `default` 的色板（只有同时注册了 `default`，才允许再用别名 `current`）。映射到推荐的 styleclass token（`background`、`foreground`、`primary` 等）。取值必须与导出一致——构建 `default` 时不要“改善”对比度、色相或渐变。
2. **首次渲染 / 启动**必须使用 `default`，除非 `localStorage` 已持有来自先前会话的**用户**选择。绝不要因为生成列表把某个现成色板排在前面，就启动到该色板。
3. `minor` / `vibe` / `country` 下的现成色板仅为**可选切换器选项**。生成它们的 CSS 可以；把其中任一设为产品默认则不可以。若故意把非 Figma 配色设成默认，须在 `sop/TODO.md` 中用明确产品理由记录（少见）。
4. **字体排印不在主题化范围内。** 不要为了匹配某个色板说明而更改 `font-family`、字重、字号阶梯、字距或行高。保留清单的 Typography 小节；只把带颜色的属性改写到 token 上。
5. **字体仍必须能解析。** 若合并运行本步骤时 Figma 字族还不在 `web/assets/fonts/`，按步骤 `010` 补完本地化：仅当字族名相同时才复用 `$HOME/.cache/fonts/` 或 `/usr/share/fonts`；否则经 `http://localhost:8118`（Google Fonts / gstatic）下载原文件，同时写入 `web/assets/fonts/` 与 `$HOME/.cache/fonts/{truetype|opentype|woff}/…`。绝不要换成“能下载到的别的字体”来让构建变绿。
6. 写出 `sop/theme-default.md`，记录 `default` 色板：
   - token → 提取值（需要时注明源文件/选择器）
   - 字体栈保持不变
   - 确认启动使用 `data-theme="default"`（或等价物）

## 应用 + 切换器

1. 实现 `applyTheme(id)` / 可选 `previewTheme(id)`：
   - 设置 `document.documentElement.dataset.theme = id`（匹配生成的 CSS）
   - 当 `type === "dark"` 时切换 `.dark`
   - **仅在用户显式切换之后**才把 id 持久化到 `localStorage`（不要事先写入现成色板的 id）
   - 启动时、首次渲染前调用一次：无用户选择时解析为 `default`
2. 添加主题控件时**不要改动 Figma 原有界面框架**：
   - 若清单中已有，优先复用既有设置 / 溢出 / 页脚控件。
   - 否则使用低调、非主视觉控件（如小菜单项或开发者入口）。**不要**发明导出所没有的醒目页头/工具条、徽章簇或营销式主题选择器。
   - 在该控件内按 `minor` / `vibe` / `country`（或 catalog 族）分组可选色板。把 `default` 列在最前，并标注为 Figma / 产品外观。
3. 复核 `sop/design-inventory.md` — 本步骤不得丢弃已列出的路由/页签，也不得改动布局、字体排印、间距或导航的样式。只通过 token 改颜色。
