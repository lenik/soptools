# 实现基于工作流的 Playwright 测试

## 准备：合并散落用例集并修订工作流

实现 Playwright 测试之前：

1. 递归扫描 `sop/` 下**所有**子目录中的散落工作文档：
   - `TUC.md` — 测试用例参考集
   - `NTC.md` — 反用例 / 负面测试
   - `ECS.md` — 边界场景
   - `TODO.md` — 活任务清单
2. 把各类**合并**进规范根文件 `sop/TUC.md`、`sop/NTC.md`、`sop/ECS.md`、`sop/TODO.md`（去重；折入既有根文件；保留有用的出处标题）。
3. 合并成功后**删除**散落副本。
4. **对工作流的二次处理（Codex）：** 用合并后的用例集修订 `web-e2e/workflows.md`——增改工作流以反映 TUC / NTC / ECS 覆盖；不要发明不受支持的产品功能；保持工作流式伪代码（不是 Playwright 源码）。

仅在合并 + 工作流修订之后，再实现下方测试。

阅读：

- `web-e2e/workflows.md`（修订后）
- `sop/TUC.md`（合并后，若存在）
- `sop/NTC.md`（合并后，若存在）
- `sop/ECS.md`（合并后，若存在）

实现覆盖全部工作流的 Playwright 测试。

用 `sop/` 测试参考确保正向用例、负面用例与边界场景不被跳过。

优先面向工作流的测试，而不是一控件一测。

测试应锻炼真实用户行为。

使用稳定选择器。

按此顺序优先：

- 可访问角色/名称
- 标签
- 合适处的占位符
- 稳定的语义 test ID

避免脆弱选择器，例如基于：

- 深层 CSS 层级
- nth-child
- 视觉位置
- 生成的类名

仅在语义选择器不足时添加 `data-testid`。

不要仅为方便 Playwright 而改动可见 UI。

## SOP 驱动的提交

**随本步骤演进**提交——每完成一块连贯切片（产物已写出、某条路由/功能已抽出、某个 mock 已替换、某子集测试已绿等）。**不要**把整步工作拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop120]` 开头。见本 SOP 包中的 `CHECKPOINT.md`。
