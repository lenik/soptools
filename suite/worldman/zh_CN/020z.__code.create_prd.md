# 从仓库证据撰写 PRD

## WorldMan 架构（先读）

写 PRD 之前，先引入并落实本模块架构：

- WorldMan 应用是轻量微服务式模块：每个既可**完全独立运行**，也可与对等应用**集成**。
- **独立模式**：应用可为共享基础数据自带**精简本地表**（例如仅联系人姓名+电话）。专用对等应用（如联系人）可把同一概念建得更完整。
- **集成模式**：对等主数据只存为**不透明 cuid2 引用**，并通过该对等应用的 API 解析——不是跨库外键。
- 主数据主键使用 **`cuid(2)`**，以便独立与集成部署下身份保持稳定。
- 标准布局：`prisma/`、`backend/`、`web/`、`web-e2e/`、可选 `mobile/` / `mobile-e2e/`、`sop/`、`docs/`、`docker/`、`i-local/`、`i-medium/`、`worldman.json`。
- 部署可为直接进程、Apache/Nginx 反代或容器。基准端口 `N` 由 `wm port -n <name>` 得到（HTTPS = HTTP+1，bridge web `80`/`443` 除外；见 SOP README）。

证据支持处，在 PRD 中体现这些约束。

## UI 结构 vs 导出噪音

把 `sop/design-inventory.md` 当作**导航与表格 UI 结构的权威**（其中列出的路由、页签、主要界面外壳、对话框）。

- 清单中状态为 `kept` / `moved` 的每条，都是要在 PRD 中文档化的产品面（工作流 + 验收），不是可选装饰。
- 不要把已列出的页签/路由降级为“偶然导出”，除非把清单更新为 `dropped:<reason>` 或带证据的 `dead`/`scaffold`。
- “偶然设计导出细节”适用于无标签空壳、重复脚手架界面，或清单已标 `dead`/`scaffold` 的控件——不适用于带真实标签/内容的独立屏幕或页签面板。

其余产品意图，从重复、语义明确的证据推断。

## 证据优先级

来源冲突时，按此顺序优先：

1. `sop/` 下已有的明确产品文档（尤其是 `sop/PRD.md`），其次 `docs/`
2. 针对路由、页签、chrome 与已列对话框的 `sop/design-inventory.md`
3. 已有 Prisma/领域定义
4. 已实现的用户可见行为
5. 稳定的 mock/fixture 数据结构
6. 孤立标签、占位文案或死导出/脚手架控件（仅当清单未标为 kept）

不要仅为了让 PRD 看起来完整而发明需求。

若重要需求无法从仓库证据判定，记在 **Open Questions / Unresolved Requirements** 下。

不要靠追问澄清来阻塞本任务。

## PRD 要求

PRD 应适合实现与后续验收测试。

在证据支持处覆盖：

- 产品概述
- 目标
- 范围
- 范围外
- 术语
- 用户角色
- 领域概念
- 核心实体
- 实体关系
- 业务规则
- 生命周期/状态迁移
- CRUD 行为
- 搜索
- 筛选
- 排序
- 相关处的分页
- 批量操作
- 相关处的导入/导出
- 媒体
- 相关处的历史/审计行为
- 外部引用
- 校验规则
- 删除/归档行为
- 空状态
- 错误行为
- 重要边界情况
- 主要 UI 工作流
- 非功能期望
- WorldMan 独立 vs 集成模型
- Open Questions / Unresolved Requirements

对每条实质推断出的需求，写到另一位开发者能实现或测试的清晰度。

证据支持时文档化 WorldMan 约束：

- 本模块的独立 vs 集成运行
- 哪些实体是自有主数据，哪些是对等模块的不透明 cuid2 引用
- 主数据主键的 `cuid(2)` 身份
- 相关处经 `wm port -n <name>` 的部署/端口期望（HTTPS = HTTP+1，bridge `80`/`443` 除外）

文档化时不要借机重设计既有产品。

证据或提示产出可测材料时，一并初始化或更新 `sop/` 下：

- `TODO.md` — 剩余重建 / 实现任务；保持状态最新
- `TUC.md` — 测试用例参考集
- `NTC.md` — 反用例 / 负面测试
- `ECS.md` — 边界场景

这些文件供后续 e2e 工作流与工具/支撑类工作使用。

把完成的产物直接写到 `sop/PRD.md`。

## SOP 驱动的提交

**随本步骤演进**提交——每完成一块连贯切片（产物已写出、某条路由/功能已抽出、某个 mock 已替换、某子集测试已绿等）。**不要**把整步工作拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop020]` 开头。见本 SOP 包中的 `CHECKPOINT.md`。
