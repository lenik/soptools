# 审计交互控件覆盖

在工作流测试实现后，审计所有交互 GUI 控件。

若存在，对照 `sop/TUC.md`、`sop/NTC.md` 与 `sop/ECS.md` 交叉检查，使已知场景不缺少控件路径。

确保每个有意义的交互控件至少被一个 E2E 测试锻炼。

在适用处包含：

- 按钮
- 链接
- 页签
- 菜单
- 上下文菜单
- 下拉
- selects
- 搜索输入
- 筛选器
- 排序控件
- 分页
- 复选框
- 单选按钮
- 开关
- 表单
- 对话框
- sheets
- drawers
- 日期/时间控件
- 文件上传
- 下载
- 媒体控件
- 拖放
- 展开/折叠控件
- 批量选择控件
- 破坏性确认

当既有工作流已覆盖该控件时，不要创建冗余测试。

目标是交互覆盖，而非测试数量膨胀。

对照 `sop/design-inventory.md` 中列出的页签与其它 chrome，使清单表面
不缺少至少一条交互路径。

## SOP 驱动的提交

**随本步骤演进**提交——在每个连贯切片之后（写出产物、
抽出一条路由/功能、替换一个 mock、子集测试转绿，…）。
**不要**把整个步骤拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop130]` 开头。见本 SOP 包中的
`CHECKPOINT.md`。
