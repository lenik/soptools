# 审计交互控件覆盖

工作流测试实现后，审计全部交互 GUI 控件。

存在时对照 `sop/TUC.md`、`sop/NTC.md`、`sop/ECS.md`，确保已知场景都有控件路径。

确保每个有意义的交互控件至少被一条 E2E 测试锻炼到。

在适用处包含：

- 按钮
- 链接
- 页签
- 菜单
- 上下文菜单
- 下拉
- 选择器
- 搜索输入
- 筛选器
- 排序控件
- 分页
- 复选框
- 单选按钮
- 开关
- 表单
- 对话框
- sheets
- drawers
- 日期/时间控件
- 文件上传
- 下载
- 媒体控件
- 拖放
- 展开/折叠控件
- 批量选择控件
- 破坏性确认

既有工作流已覆盖某控件时，不要创建冗余测试。

目标是交互覆盖，不是把测试数量做大。

对照 `sop/design-inventory.md` 中列出的页签及其它界面外壳，确保清单面至少有一条交互路径。

## SOP 驱动的提交

**随本步骤演进**提交——每完成一块连贯切片（产物已写出、某条路由/功能已抽出、某个 mock 已替换、某子集测试已绿等）。**不要**把整步工作拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop130]` 开头。见本 SOP 包中的 `CHECKPOINT.md`。
