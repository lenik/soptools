# 运行并修复 E2E 测试

运行完整的 Playwright 测试套件。

对失败：

1. 判定失败属于：
   - 产品实现缺陷
   - 后端缺陷
   - 集成缺陷
   - 测试缺陷
   - 不稳定选择器
   - 错误的测试数据假定

2. 在正确的一层修复。

不要仅为让测试通过而削弱测试。

除非工作流与既定产品规格矛盾，否则不要改预期工作流。

重复直到所有已定义工作流都能工作。

## 跑完后清理测试数据

Playwright（以及配套后端）套件结束后——**无论通过或失败**——离开本步骤前，删掉共享库里残留的仅测试用行。优先依赖测试自身的拆卸；若仍有污染（崩溃跑残留、缺少 `afterAll` 等）：

1. 识别带测试标记的行（前缀 / 标签 / 已知 fixture 名）。
2. 经 API 或检入 `web-e2e/` / `scripts/` 的一次性清理脚本删除（**不要**对 seed/demo 表整表 `TRUNCATE`）。
3. 加固出问题测试的拆卸，让下次运行保持干净。

套件变绿但库里仍堆着上百条测试实体，不算做完。

## SOP 驱动的提交

**随本步骤演进**提交——每完成一块连贯切片（产物已写出、某条路由/功能已抽出、某个 mock 已替换、某子集测试已绿等）。**不要**把整步工作拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop140]` 开头。见本 SOP 包中的 `CHECKPOINT.md`。
