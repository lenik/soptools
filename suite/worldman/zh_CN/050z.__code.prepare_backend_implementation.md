# 准备基于仓库的后端实现

这是 GPT 步骤（通常会生成后端实现提示词）的 Codex 回退路径。

你已在仓库内操作，因此不要生成一份打算再粘贴回 Codex 的提示词。

改为：检查仓库、准备具体实现计划，并把仓库留在可进入后端实现步骤的状态。

至少审阅：

- `sop/PRD.md`
- `sop/TUC.md`（若存在）
- `sop/NTC.md`（若存在）
- `sop/ECS.md`（若存在）
- `sop/TODO.md`（若存在）
- `prisma/schema.prisma`
- `prisma/seed.ts`
- `web/`
- `package.json`
- `pnpm-workspace.yaml`
- 既有 `backend/`

同时检查：

- web 路由
- 前端数据/服务抽象
- mock 数据
- 既有请求/响应形态
- 领域枚举与状态迁移
- 搜索/筛选/排序行为
- 批量操作
- 跨实体导航
- 看起来可超出当前 UI 复用的功能

抽取共享工具或支撑类时，优先采用 `sop/` 下已捕获的需求与场景（`PRD.md`、`TUC.md`、`NTC.md`、`ECS.md`）。

计划项完成或推迟时，保持 `sop/TODO.md` 状态最新。

## 产出

同时写出：

```text
docs/backend-implementation-plan.md
sop/Backend implementation prompt.md
```

- `docs/backend-implementation-plan.md` — 面向人的详细计划 / 缺口说明。
- `sop/Backend implementation prompt.md` — 步骤 `060` 会检出的可直接照着实现的说明（路径与 chat 轨的 `Save-As` 相同）。从计划推导：具体架构、路由分组、工作顺序与约束，使 `060` 无需 chat 轨也能推进。

## 后端假定

目标：

- `pnpm`
- Node.js
- TypeScript

API 前缀：`/api/v1/`

后端须暴露有用的领域能力，而不仅是当前 web UI 所需的最小端点。

对每个领域资源，评估是否真正需要：

- CRUD
- list
- detail
- search
- lookup
- autocomplete
- filtering
- sorting
- pagination
- batch retrieval
- bulk create/update/delete
- relation traversal
- tree traversal
- state transitions
- history
- version access
- validation
- statistics
- aggregation
- import
- export
- media operations
- external reference resolution

不要机械地为每个模型规定全部能力。

计划应定义：

- 后端架构
- 领域/服务边界
- 路由分组
- 校验策略
- 错误模型
- 序列化约定
- 分页约定
- 筛选/排序约定
- 资源能力
- 领域专用操作
- 批量操作语义
- 测试策略
- 与 web/ 的集成关切
- 实现顺序

优先分离：

- route/controller 层
- 校验
- 服务/领域逻辑
- 数据访问
- 共享错误
- API 序列化

不要把领域逻辑直接放在路由处理器里。

## 基于仓库的缺口处理

若 `sop/PRD.md`、`schema.prisma`、seed 数据与 web 应用不一致：

- 在 `docs/backend-implementation-plan.md` 中记录矛盾
- 标明哪个来源更权威及理由
- 选择破坏最小、可逆的实现假定
- 不要静默重设计 schema 或产品

若存在 `prisma/request-for-refactor.md` 或 `sop/Backend amends.md`，审阅并把相关阻塞项折入实现计划。Schema 与后端修订在实现后端时应用：合并这些文件，然后删除它们。

除非调用本文件的工作流明确要求合并规划与实现，否则本步不要实现后端。

来源冲突时，用户可见面优先 `sop/design-inventory.md` + 当前 `web/` 行为，持久化形态优先 `schema.prisma` / seed——记录冲突，而不是为了迁就稀疏 API 计划去削薄 UI。

## SOP 驱动的提交

**随本步骤演进**提交——每完成一块连贯切片（产物已写出、某条路由/功能已抽出、某个 mock 已替换、某子集测试已绿等）。**不要**把整步工作拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop050]` 开头。见本 SOP 包中的 `CHECKPOINT.md`。
