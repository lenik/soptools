# 实现基于工作流的 Playwright 测试

## 准备工作：合并散落用例集并由 Codex 二次加工 workflows

在实现 Playwright 测试之前：

1. 递归扫描 `sop/` 下**所有**子目录中散落的工作文档：
   - `TUC.md` — 测试用例参考集
   - `NTC.md` — 反用例 / 负面测试用例
   - `ECS.md` — 边界场景
   - `TODO.md` — 实时任务清单
2. 将各类**合并**为根目录规范文件 `sop/TUC.md`、`sop/NTC.md`、`sop/ECS.md`、
   `sop/TODO.md`（去重；并入已有根文件；可保留来源说明）。
3. 合并成功后**删除**散落副本。
4. **对 workflows 二次加工（Codex）：** 依据合并后的用例集修订
   `web-e2e/workflows.md` — 增补或调整工作流以覆盖 TUC / NTC / ECS；不要发明
   未支持的产品功能；保持工作流式伪代码（不是 Playwright 源码）。

完成合并与 workflows 修订后，再实现下列测试。

阅读：

- `web-e2e/workflows.md`（修订后）
- `sop/TUC.md`（合并后，若存在）
- `sop/NTC.md`（合并后，若存在）
- `sop/ECS.md`（合并后，若存在）

实现覆盖全部工作流的 Playwright 测试。

使用 `sop/` 测试参考，确保正向用例、反用例与边界场景不被跳过。

优先面向工作流的测试，而不是每个控件一个测试。

测试应锻炼真实用户行为。

使用稳定选择器。

按此顺序优先：

- 可访问的 role/name
- label（标签）
- placeholder（在合适时）
- 稳定语义 test ID

避免基于以下内容的脆弱选择器：

- 深层 CSS 层级
- nth-child
- 视觉位置
- 生成的类名

仅在语义选择器不足时添加 `data-testid`。

不要仅为让 Playwright 更容易而改动可见 UI。
