# 重构 Figma 生成的 web 应用

审计并重构 `web/` 下由 Figma 导出的 WorldMan UI。

## 设计清单（必需 — 先做这一步）

在拆分文件、移动路由、重命名处理器或本地化资源**之前**，先固化 Figma 基线，以免后续步骤静默毁掉它。

1. 检查 `web/`，以及步骤 `000` 保留的 `sop/figma-archive/`（若存在）。
2. 写出 `sop/design-inventory.md`，至少包含：

```markdown
# Design inventory (Figma baseline)

Captured at step 010 **before** structural refactor. Later steps must not
silently drop entries. Removals require an explicit status + reason here.

## Routes
| path | title / label | source file(s) | status |
|------|---------------|----------------|--------|
| …    | …             | …              | kept   |

## Tabular / tabbed surfaces
| parent route or screen | tab id / label | content summary | status |
|------------------------|----------------|-----------------|--------|
| …                      | …              | …               | kept   |

## Major chrome / navigation
| area | description | status |
|------|-------------|--------|

## Dialogs / sheets / drawers / menus
| name | opened from | status |
|------|-------------|--------|

## Mock / demo data sources
| path or symbol | entities | approx rows / examples | notes |
|----------------|----------|------------------------|-------|

## Typography / fonts (baseline)
| family / stack | weights / styles used | where referenced | status |
|----------------|----------------------|------------------|--------|
| …              | …                    | …                | kept   |

## Color / surface notes (optional but useful for 011)
| role guess (bg/text/accent/…) | sample value or class | notes |
|-------------------------------|----------------------|-------|
```

3. 状态取值：`kept` | `moved:<new path>` | `dropped:<reason>` | `dead` / `scaffold`（仅用于明显非产品的导出脚手架）。
4. 在本文件存在、且已列出你能找到的每条可导航路由与每个页签/表格面之前，**不要**开始结构性编辑。

本步（及后续步骤）的硬性保真规则：

- 不得丢弃已列出的路由或页签，除非在清单中写明具体理由（产品矛盾、重复路由等）。
- “简化”“清理”或“以后再重建”**不是**有效的丢弃理由。
- 除非修复明显的 Figma 生成缺陷（坏布局、无标签/无动作的空壳控件），否则保留既有视觉设计与交互模型。
- **不要改字体，也不要“升级”字号阶梯。** 保留 Figma 的 `font-family` 栈、字重与字号。把字体文件本地化可以；换成 Inter / system-ui / 主题色板推荐的展示字体不可以。

然后检查当前应用并识别：

- 路由与页面
- 过大的 TSX 文件
- 页面级组件
- 共享组件
- 对话框、sheet、drawer 与 popover
- 表单
- 表格与列表
- 搜索、筛选与排序行为
- 菜单与上下文菜单
- CRUD 操作
- 本地/mock 数据源
- 本地持久化
- 交互控件
- 未完成或死控件

再在有用处重构结构。

## 文档标题（必需）

Figma Make 导出常把浏览器标签默认成 **`Figma Make App`**（多半经
`web/vite.config.ts` → `figmaSiteConfiguration` / `<!-- figma:title -->`）。
改成 WorldMan 身份串：

```text
{族} | {代码} | {标题}
```

示例：`ClassMate | CM-Ballet | ClassMate Ballet`

### 三部分如何取

| 部分 | 含义 | 取值顺序 |
|------|------|----------|
| **族** | 产品族 / 品牌线 | 项目根目录的上一级（布局为 `<族>/<代码>/` 时，如 `classmate` → 优先用 UI / `worldman.json` 标题里已有的品牌写法，如 `ClassMate`）；否则用界面外壳里可见的品牌前缀 |
| **代码** | 模块 / 应用代号 | **项目根**目录名（如 `CM-Ballet`）— 保留连字符与原有大小写 |
| **标题** | 可读产品名 | 有则用 `worldman.json` 的 `"title"`；否则用应用内产品名（顶栏 / PRD）；**禁止**残留 `Figma Make App` |

### 写到哪里

1. 把解析出的字符串接到所有喂给 `<title>` 的地方：
   - `web/index.html` 的 `<title>…</title>` / `<!-- figma:title -->` 槽
   - `web/vite.config.ts`（或仍在用的 `.figma/make/site.json`），使
     `figmaSiteConfiguration` **不再**回落到 `"Figma Make App"`
2. 只保留**一份**规范字符串 — 静态 HTML 与 Vite HTML 变换必须一致；不要一处自定义、另一处仍是默认值。
3. `og:title` 可用同一字符串。
4. **不要**再加第四段；分隔符为 ` | `（空格-竖线-空格）。
5. 若 `worldman.json` 没有 `"title"`，能定名时补上；本步仍须设好文档标题。

## 本地化 Figma demo 资源

Figma Make 原型常热链远程 demo 媒体（图片、字体、音频、视频、Lottie 等）。本次重构要使 UI 自包含：

1. 扫描 `web/` 中作为 demo 资源使用的绝对 `http(s)://` URL（CSS `@import` / `@font-face`、`<img>` / `<audio>` / `<video>`、背景 URL、媒体的 fetch/import 等）。
2. 按原样把每个资源下载到 `web/assets/`，可按类型分组：
   ```text
   web/assets/
       images/
       fonts/
       audio/
       video/
       …
   ```
   下载时，Google / Google Fonts / gstatic、Facebook / fbcdn 等主机**必须**走本地 HTTP 代理 `http://localhost:8118`（经 `http_proxy` / `https_proxy`，或 curl/wget `--proxy`）。不要长时间直连这些主机。其它 CDN 可先直连；失败再经代理重试，直到拿到真实文件。不要放弃，也不要用假资源顶替。
3. 把所有引用改写为本地路径或模块导入。文件名宜稳定、可读；保留资源自带的许可或署名说明。
4. 对**字体**（硬性规则——Google Fonts / gstatic 常需代理才能访问）：
   - **保留原字族。** 不要换成 Inter / system-ui / 主题色板推荐字体。CSS 中保持相同的 `font-family`、字重与样式。
   - **下载前先复用**，顺序：
     1. 项目里已有 `web/assets/fonts/`
     2. `$HOME/.cache/fonts/` 下同名字族（能区分时再匹配字重/样式）
     3. `/usr/share/fonts/` 或 `$HOME/.local/share/fonts/` 中已安装的同名字体——**复制**进项目（不要在已提交 CSS 里写死本机路径）
   - 以上都没有**同名字体**时，**必须下载**远程真实的 `@font-face` 文件。Google / Google Fonts / gstatic **必须**走 `http://localhost:8118`。不要因为 CDN 超时就跳过、用假字体，或换近似字体凑合。
   - 文件要写到**两处**：
     - 项目：`web/assets/fonts/…`（应用随包分发）
     - 缓存：`$HOME/.cache/fonts/…`（跨项目共用）
   - 缓存目录结构参考 `/usr/share/fonts`，按格式 / 字族组织，例如：
     ```text
     $HOME/.cache/fonts/
         truetype/<FamilyName>/…
         opentype/<FamilyName>/…
         woff/<FamilyName>/…          # .woff / .woff2
     ```
   - 路径变了但字族不变时，更新 `sop/design-inventory.md` → Typography。
5. 提交源码中不要留下 demo CDN / 素材热链。跳过非资源 API 端点与有意的第三方集成。

**许可与真实性（重要）：** Figma 原型里的热链通常条款很宽松。例如 Unsplash 照片使用 [Unsplash License](https://unsplash.com/license)：个人与商用免费，无需付费、无需摄影师许可、无需署名（亦见[讨论](https://www.zhihu.com/question/50969084)）。这对开发与原型验证特别友好。本应用不是图库平台，也不与这类服务竞争。**不要过度解读许可约束。** 不要跳过下载，也不要用占位图、纯色块、假图或其它替代物顶替真实媒体——把远程资源原样存进 `web/assets/`。

## 页面抽取

在合适时，从过大或单体 TSX 中抽出路由级页面。

按职责组织结构：

```text
src/
    pages/
    features/
    components/
    hooks/
    services/
    lib/
```

### 目录职责（Vite + React — 不是 Next.js）

| 目录 | 职责 |
|------|------|
| `pages/` | **路由边界** — 每个可导航屏面对应一个入口模块（路由器 + 路由冒烟枚举） |
| `features/` | 页面专属 UI、状态与领域分块 |
| `components/` | 跨路由/功能共享的可复用 UI |

规则：

- 仅当真实页面主体位于 `features/`（如 `features/foo/…`）时，才允许薄的 `pages/FooPage.tsx` 再导出。
- **不要**把完整页面实现放在 `components/`，却让 `pages/` 只剩对这些组件的空再导出。
- 拆分含页签的单体屏幕时，保持**所有**页签可到达。优先单路由 + 内部页签，或每页签一条子路由——无论哪种都要更新 `sop/design-inventory.md`。绝不要因为“文件太长”就删掉页签内容。

过大文件**必须**拆分。文件过长通常意味着结构不对：缺少经 services、discovery 等机制的去中心化，和/或应抽到独立外部源文件的工具/支撑代码。

按以下边界拆分：

- 路由边界
- 功能边界
- 状态归属
- 可复用 UI 职责
- 领域操作
- 共享服务 / discovery / 工具支撑抽到专用模块

除非结构性变更必要，否则保留既有视觉设计与交互模型。

## UI 可测性重构

重构 UI 逻辑，使自动化测试与维护更容易。

业务逻辑不得直接写在匿名 JSX 回调里。

匿名回调只可：

- 转发参数
- 提取事件值
- 把事件适配为对命名处理器的调用

不好的写法：

```tsx
<button
    onClick={async () => {
        setLoading(true)
        await api.deleteItem(item.id)
        refresh()
        setLoading(false)
    }}
>
```

推荐：

```tsx
async function performDeleteItem(id: string) {
    ...
}

function handleDeleteItemClick(id: string) {
    void performDeleteItem(id)
}
```

对基于事件的行为，在可行时把事件提取与事件无关行为分开。

示例：

```tsx
function performSeek(timestamp: number) {
    ...
}

function handleTimelineClick(event: MouseEvent) {
    const timestamp = extractTimestamp(event)
    performSeek(timestamp)
}
```

使用清晰命名，例如：

- `performCreateItem`
- `performDeleteItem`
- `performSave`
- `performSearch`
- `handleSaveClick`
- `handleFilterChange`
- `handleDialogOpen`
- `handleDialogClose`

避免不必要地绑定视觉位置的名字（如 `button1_click`），除非没有有意义的语义名。

## 根 `package.json` 脚本（必需）

确保**仓库根**是 pnpm workspace 父包，并具备常用脚本目标。创建或更新：

- `pnpm-workspace.yaml` — 至少包含 `.`、`web`、`backend`、`prisma`、`web-e2e`（当 `mobile` / `mobile-e2e` 是真实包时再加入）
- 根 `package.json` — `private: true`；若用 `dev` 同时拉起多个子进程，把 `concurrently` 加进 `devDependency`；以及下表脚本

仅有 `web/package.json` 不够：后续步骤与运维人员从仓库根运行（`pnpm dev`、`pnpm db:migrate`、`pnpm e2e`）。

### 必需的根脚本

| 脚本 | 转发到 | 用途 |
|------|--------|------|
| `dev` | `concurrently -kic blue,green npm:dev:*` | 一并运行全部 `dev:*` |
| `dev:web` | `pnpm -C web dev` | Vite（或等价）web |
| `dev:backend` | `pnpm -C backend dev` | API 进程 |
| `db:generate` | `pnpm -C prisma generate` | `prisma generate`（以及 generate 之后的链接等钩子） |
| `db:migrate` | `pnpm -C prisma migrate` | **`prisma migrate deploy`** — 应用已有迁移（CI / 生产 / 共享库） |
| `db:migrate:dev` | `pnpm -C prisma migrate:dev` | **`prisma migrate dev`** — 本地开发中创建并应用 |
| `db:push` | `pnpm -C prisma db:push` | 使用时的 `prisma db push` |
| `db:seed` | `pnpm -C prisma seed` | Seed |
| `db:studio` | `pnpm -C prisma studio` | Studio |
| `e2e` | `pnpm -C web-e2e test` | Playwright（存在时再加 `:smoke` / `:report`） |

后续可选（包存在时）：`mobile`、`mobile:*`、`e2e:smoke` 等。

### 命名规则（不要发明重复别名）

- 仓库根上的 Prisma/数据库任务统一用 **`db:*`** 前缀。**不要**再在根上提供 `prisma:generate` / `prisma:migrate`——那是同命令的另一套名字。
- **`db:migrate`** 与 **`db:migrate:dev`** 必须是**两个**脚本——它们**不是**一回事：
  - `db:migrate` → `migrate deploy`（非交互应用）
  - `db:migrate:dev` → `migrate dev`（交互式编写）
- **不要**再加只是重复 `db:migrate` 的第三个别名（如 `db:deploy`）。
- 在 `prisma/package.json` 内用根脚本转发到的短名：`generate`、`migrate`（= deploy）、`migrate:dev`、`db:push`、`seed`、`studio`。首次添加 `prisma/package.json` 时对齐（步骤 `030` / `060`）；本步至少先把根脚本接好，方便后续包干净接入。
- `backend/package.json` 可为本地 DX 调用 `../prisma`；运维入口仍以根上的 `pnpm db:*` 为准。

若根 `package.json` 已存在（重跑 / 半成品树），**合并**这些脚本，不要删掉无关脚本；把过时的根 `prisma:*` 别名改名为 `db:*`。

### 不把 lock 文件纳入 git（必需）

WorldMan 项目**不在**版本库中保留包管理器 lock 文件。安装以 `package.json` /
workspace 为准；lock 文件易产生无意义 diff，并在不同机器间造成钉死漂移。

1. 确保根 `.gitignore` 至少包含：

```gitignore
pnpm-lock.yaml
package-lock.json
yarn.lock
```

2. 若 `pnpm-lock.yaml`（或其他 lock 文件）已被跟踪：

```bash
git rm -f --cached pnpm-lock.yaml package-lock.json yarn.lock 2>/dev/null || true
```

   工作区里的文件可保留——只取消跟踪。
3. **不要**在后续提交中再加回 lock 文件。用 `pnpm install` 即可，生成的
   lockfile 不要提交。
4. 本步接线根脚本时，把上述 ignore 规则放进同一笔 `[sop010]` 提交。

## 项目 `sop/` 工作区

本次重构及后续复杂构建步骤中，在 `sop/` 下维护工作文档：

- 把 `sop/TODO.md` 当作活任务清单；随工作推进更新条目状态。
- 有意移动结构时，保持 `sop/design-inventory.md` 最新。
- 用户给出复杂提示时，尽快把候选测试提取或整理进：
  - `sop/TUC.md` — 测试用例参考集
  - `sop/NTC.md` — 反用例 / 负面测试
  - `sop/ECS.md` — 边界场景
- 产品需求在 `sop/PRD.md`（由 PRD 步骤撰写）。
- 抽取共享工具/支撑类、以及编写后续 e2e 覆盖时，优先参考这些 `sop/` 文档。

### 钉住 SOP 模板版本（必需）

写出（或刷新）`sop/template-version`，以便日后流程包升级时对照 changelog，而不必猜测项目当初用的是哪一版。

1. 读取当前加载的包里的 `suite/worldman/VERSION`（sopwin 加载的目录——通常是本步骤文件所在语言分支的上一级，即 `default/` / `zh_CN/` 的父目录）。
2. 写入项目文件 `sop/template-version`，内容为：

```text
suite=worldman
version=MAJOR.MINOR.PATCH
```

   将 `MAJOR.MINOR.PATCH` 换成 VERSION 文件中的值（不要加 `v` 前缀）。
3. 键上方可用 `#` 开头的注释行。
4. **不要编造版本**；若缺少 VERSION，先修好 suite 包再继续。
5. 日后 WorldMan 包升级时，用 `sop/template-version` 对照 `suite/worldman/CHANGELOG.md` 与 `suite/worldman/RETROFIT-zh_CN.md`，补做缺项（自我迭代），不必从零重跑每一步。

本阶段除非修复明显的 Figma 生成缺陷，否则不要改产品行为。

## SOP 驱动的提交

**随本步骤演进**提交——每完成一块连贯切片（产物已写出、某条路由/功能已抽出、某个 mock 已替换、某子集测试已绿等）。**不要**把整步工作拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop010]` 开头。见本 SOP 包中的 `CHECKPOINT.md`。

当 `011` 主题化经 `extend: previous` 并入本步骤时，那些提交仍用 `[sop010]`（图上一步）。
