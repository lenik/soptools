# 撰写最终 API 文档

在后端实现与集成稳定后，撰写完整的 `docs/api.md`。

本文档描述实际已实现的 API。

它是建成态 API 合同。

文档化：

- API 基路径
- 通用约定
- 适用时的认证
- 请求格式
- 响应格式
- 错误格式
- 分页
- 筛选
- 排序
- 搜索
- 批量操作约定
- 资源端点
- 状态转换端点
- 关系端点
- 领域特定端点
- 示例
- 重要校验规则
- 重要冲突行为

对每个端点包含足够信息，使另一应用无需阅读后端源码即可使用该 API。

不要文档化不存在的端点。

不要仅仅因为当前 web 应用未调用就省略有用的已实现端点。

## SOP 驱动的提交

**随本步骤演进**提交——在每个连贯切片之后（写出产物、
抽出一条路由/功能、替换一个 mock、子集测试转绿，…）。
**不要**把整个步骤拖到步骤末尾一次提交。

SOP 驱动的主题必须以 `[sop090]` 开头。见本 SOP 包中的
`CHECKPOINT.md`。
