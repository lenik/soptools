# 集成 Web 与后端

把 `web/` 接到 `backend/`，让界面使用真实 API。

## 目标

- 在合适处用后端 API 替换演示、mock 和仅本地的数据源。
- 保留已批准的 UI 结构与视觉设计；不要只因为正在做集成就重做产品界面。
- 建立清晰的前端 API/服务层（优先 `web/src/services/` 或等价客户端模块）。避免在页面组件里到处散落原始 `fetch()`。

## UI 行为

确保界面正确处理：

- 加载中
- 空状态
- 服务器错误
- 校验错误
- 未找到
- 冲突
- 保存成功
- 删除/归档确认
- 刷新
- 重新加载后的持久化
- 搜索
- 过滤
- 排序
- 分页

对大型或可复用的数据集，在适合时优先使用服务端能力。

## 当集成暴露后端问题时

若集成暴露出真实的后端设计问题，按需重构后端。当后端行为变化时：

- 更新后端测试
- 保持公开 API 一致
- 重新运行后端测试
