# Theme the web UI (WorldMan styleclasses)

Apply semantic theming to `web/` using the project theme fork at `sop/themes/`.
This step extends the structural refactor in `010` (`extend: previous`).

`sop/themes/` is a **project-local fork** of the suite attachment
`suite/worldman/themes/` (seeded by step `000`). Evolve it for this product —
add/rename palettes, adjust HSL, trim country packs — without depending on the
upstream minor-themes archive at project time.

If `sop/themes/` is missing, copy from the suite pack first (including
`scripts/`). Layout:

```text
sop/themes/
  catalog/          # color-language prose
  minor|vibe|country/  ui|token|web|erp-palettes.mjs
  scripts/generate-theme-css.mjs   # forkable CSS generator
  catalog.tsv
  ELEMENTS.md / SCHEMA.md
```

## Recommended primary styleclass names

WorldMan web apps are **recommended** to use these primary styleclass /
CSS-variable stems so shared modules stay consistent. Prefer utilities bridged
from them (`bg-background`, `text-primary`, …). Projects may extend or rename
when needed — document deliberate departures in `sop/TODO.md`.

| styleclass | Role |
|------------|------|
| `background` | App / page canvas |
| `foreground` | Default body text |
| `primary` | Brand / main action |
| `primary-foreground` | Text/icons on primary |
| `card` | Raised surface |
| `card-foreground` | Text on card |
| `accent` | Selection / soft highlight |
| `accent-foreground` | Text on accent |
| `muted-foreground` | Secondary / hint text |
| `border` | Borders / dividers |
| `ring` | Focus ring |
| `destructive` | Danger / delete |
| `success` | Positive status |
| `warning` | Caution status |

Wire them as `--${name}` on `:root` (and `.dark` when needed), bridged through
the CSS framework (e.g. Tailwind `@theme`). Shared controls should consume
these tokens when practical.

Migrate hardcoded colors (`bg-blue-500`, `text-gray-900`, `bg-[#007AFF]`, …)
to these roles. Keep rare literal colors only where photo/map/canvas contrast
truly requires them.

## Generate CSS from `sop/themes/` (required)

Do **not** hand-maintain app theme CSS that duplicates palette HSL. Generate
stylesheet(s) from the fork with the shipped script (customize under
`sop/themes/scripts/` as the project evolves):

```bash
# from project root
node sop/themes/scripts/generate-theme-css.mjs
# default out: web/src/styles/themes/themes.css (+ themes-web.css, …)
node sop/themes/scripts/generate-theme-css.mjs --out web/src/styles/themes --sets web,ui
```

Import the generated CSS in `web/` and drive switching with `data-theme="<id>"`
(see catalog.tsv). Re-run the generator after palette edits.

## Load palettes — all class sets by semantics

WorldMan **web** theming is **not** limited to `webPalettes`. Use whichever
class set matches the real UI meaning (generator `--sets`):

| Source | When to use in `web/` |
|--------|------------------------|
| `web-palettes.mjs` | App chrome, pages, buttons, status (default product UI) |
| `ui-palettes.mjs` | Dense tool / IDE-like chrome (panels, tabs, sidebars) |
| `erp-palettes.mjs` | Lists, forms, amounts, workflow status |
| `token-palettes.mjs` | Code / formula / highlight surfaces |

1. Read `sop/themes/catalog.tsv` for id → `group` + `paletteKey` + catalog md.
2. Prefer generating CSS via `scripts/generate-theme-css.mjs` rather than
   importing `.mjs` at runtime in the browser.
3. Keep `catalog/<Family>.md` as the aesthetic brief.
4. Prefer the recommended **web** primary names above for shared components;
   map other sets onto CSS variables with a clear prefix (`--ui-*`, `--erp-*`,
   `--tok-*`) so they do not collide.

Preview scenes: open `sop/themes/index.html` via a local static server.

Semantic fg/bg pairs are contrast-checked (≥ 4.5:1) in the suite pack
(`tools/check-theme-contrast.mjs`). Country packs cover **zfr L2 + L3**.

## Secondary / mid tones

Do **not** invent a second naming scheme. Optional secondary tokens may be
**generated** when omitted — adjust lightness / saturation from the primaries
(same craft spirit as minor-themes mid-tones, but for web roles), e.g. `muted`,
`secondary`, `popover`, `input-background`, `sidebar*`, `app-canvas`, and
status `*-foreground` pairs. Extend `generate-theme-css.mjs` if the project
needs mid-tone synthesis.

## Preserve current look as default

When wiring themes, **keep the project's existing Figma / CSS colors as the
default**. Map those live colors into WorldMan styleclass tokens first (a
`default` / `current` pack or boot values that match the export).

Do **not** silently replace the UI with stock `innocent` (or any other pack)
just because theming landed. Stock packs under `minor` / `vibe` / `country`
are **optional switcher choices**; the first paint should still look like the
current product.

## Apply + switcher

1. Implement `applyTheme(id)` / optional `previewTheme(id)`:
   - set `document.documentElement.dataset.theme = id` (matches generated CSS)
   - toggle `.dark` when `type === "dark"`
   - persist id in `localStorage`
   - call once at boot before first paint when practical
2. Add a **visible** theme control in app chrome (settings / header / footer).
   Group by `minor` / `vibe` / `country` (or catalog family).
3. Default = **current product colors** (see above). Note any deliberate
   stock-pack default in `sop/TODO.md`.

Preserve layout and interaction; theming changes color through tokens only.
