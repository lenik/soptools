# Implement workflow-based Playwright tests

## Preparation: merge scattered case sets and revise workflows

Before implementing Playwright tests:

1. Recursively scan **all** subdirectories under `sop/` for scattered working
   documents:
   - `TUC.md` — test use-case reference set
   - `NTC.md` — negative / anti test cases
   - `ECS.md` — edge-case scenarios
   - `TODO.md` — live task list
2. **Merge** each kind into the canonical root files `sop/TUC.md`,
   `sop/NTC.md`, `sop/ECS.md`, and `sop/TODO.md` (dedupe; fold into any
   existing root file; keep useful provenance headings).
3. **Remove** the scattered copies after a successful merge.
4. **Secondary pass on workflows (Codex):** using the merged case sets, revise
   `web-e2e/workflows.md` — add or adjust workflows so TUC / NTC / ECS coverage
   is reflected; do not invent unsupported product features; keep workflow-style
   pseudocode (not Playwright source).

Only after merge + workflow revision, implement the tests below.

Read:

- `web-e2e/workflows.md` (after revision)
- `sop/TUC.md` (after merge, if present)
- `sop/NTC.md` (after merge, if present)
- `sop/ECS.md` (after merge, if present)

Implement Playwright tests covering all workflows.

Use `sop/` test references to ensure positive cases, negative cases, and edge scenarios are not skipped.

Prefer workflow-oriented tests rather than one-test-per-control.

Tests should exercise real user behavior.

Use stable selectors.

Prefer, in order:

- accessible role/name
- label
- placeholder where appropriate
- stable semantic test ID

Avoid brittle selectors based on:

- deep CSS hierarchy
- nth-child
- visual position
- generated class names

Add `data-testid` only where semantic selectors are insufficient.

Do not alter visible UI merely to make Playwright easier.
