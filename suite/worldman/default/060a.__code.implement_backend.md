# Implement backend

Checkout `sop/Backend implementation prompt.md` and implement the backend under `backend/`.

## Prisma package

Inspect the existing `prisma/` directory first. Expect at least:

- `prisma/schema.prisma`
- `prisma/seed.ts` (if already authored)
- `prisma/package.json` (add if missing)

Use this package; do not invent a second Prisma root.

## Amend merge

Seed may have left amend requests after discovering gaps against an existing
backend design prompt or `backend/` tree:

- `prisma/request-for-refactor.md` — schema changes
- `sop/Backend amends.md` — backend/API changes implied by those discoveries

Merge them **before** or **as** you implement; do not build against a known-insufficient schema/API.

### Merge schema amends

If `prisma/request-for-refactor.md` exists:

1. Read every issue in that file.
2. Apply **blocking** items to `prisma/schema.prisma` (and related prisma files such as `comments.sql` when needed).
3. Apply **recommended** items when they are small, reversible, and required for a coherent API; otherwise note deferral in the implementation notes (not by keeping the request file).
4. Update `prisma/seed.ts` so it still matches the revised schema.
5. **Remove** `prisma/request-for-refactor.md` when done.

### Merge backend amends

If `sop/Backend amends.md` exists:

1. Read every requested API/behavior change.
2. Fold those amends into the implementation under `backend/` (and keep them consistent with the merged schema/seed).
3. Prefer adjusting the design from `sop/Backend implementation prompt.md` where the amends conflict — seed/schema pressure wins for correctness.
4. **Remove** `sop/Backend amends.md` when done.

## Backend

Ensure the repository can install and run with pnpm.

Implement the backend API under `/api/v1/`.
