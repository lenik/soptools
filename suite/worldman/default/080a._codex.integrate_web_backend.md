# Integrate web with backend

Connect `web/` to `backend/` so the UI uses the real API.

## Goals

- Replace demo, mock, and local-only data sources with backend APIs where that is appropriate.
- Keep the approved UI structure and visual design. Do not redesign the app just because integration is in progress.
- Introduce a clear frontend API/service layer (prefer `web/src/services/` or an equivalent client module). Avoid scattering raw `fetch()` calls across page components.

## UI behavior

Make sure the UI handles these cases correctly:

- loading
- empty state
- server error
- validation error
- not found
- conflict
- save success
- delete/archive confirmation
- refresh
- reload persistence
- search
- filter
- sort
- pagination

Prefer server-side behavior for large or reusable datasets when that fits the domain.

## When integration reveals backend issues

If integration exposes a real backend design problem, refactor the backend as needed. When backend behavior changes:

- update backend tests
- keep the public API consistent
- re-run the backend tests
