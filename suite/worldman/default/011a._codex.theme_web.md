# Theme the web UI (WorldMan styleclasses)

Apply semantic theming to `web/` using the project theme attachment at
`sop/themes/`. This step is separate from the structural refactor in `010`.

If `sop/themes/` is missing, copy from the suite pack
`suite/worldman/themes/` (sibling of the language branch) first.

Do **not** depend on the minor-themes archive at project time. Sources are
grouped under `sop/themes/` — see `ELEMENTS.md` / `SCHEMA.md`:

```text
sop/themes/
  catalog/          # color-language prose (Yesterday.md, X-Files.md, …)
  minor/            # soft / pride — ui|token|web|erp-palettes.mjs
  vibe/             # media / retro
  country/          # cultural country palettes
  catalog.tsv
```

## Fixed primary styleclass names

WorldMan web apps **must** use these primary styleclass / CSS-variable stems so
modules stay consistent. Prefer utilities bridged from them
(`bg-background`, `text-primary`, …):

| styleclass | Role |
|------------|------|
| `background` | App / page canvas |
| `foreground` | Default body text |
| `primary` | Brand / main action |
| `primary-foreground` | Text/icons on primary |
| `card` | Raised surface |
| `card-foreground` | Text on card |
| `accent` | Selection / soft highlight |
| `accent-foreground` | Text on accent |
| `muted-foreground` | Secondary / hint text |
| `border` | Borders / dividers |
| `ring` | Focus ring |
| `destructive` | Danger / delete |
| `success` | Positive status |
| `warning` | Caution status |

Wire them as `--${name}` on `:root` (and `.dark` when needed), bridged through
the CSS framework (e.g. Tailwind `@theme`). Shared controls (Button, Input,
Card, …) must consume these tokens.

Migrate hardcoded colors (`bg-blue-500`, `text-gray-900`, `bg-[#007AFF]`, …)
to these roles. Keep rare literal colors only where photo/map/canvas contrast
truly requires them.

## Load palettes — all class sets by semantics

WorldMan **web** refactor is **not** limited to `webPalettes`. Use whichever
class set matches the real UI meaning:

| Source | When to use in `web/` |
|--------|------------------------|
| `web-palettes.mjs` | App chrome, pages, buttons, status (default product UI) |
| `ui-palettes.mjs` | Dense tool / IDE-like chrome (panels, tabs, sidebars) |
| `erp-palettes.mjs` | Lists, forms, amounts, workflow status |
| `token-palettes.mjs` | Code / formula / highlight surfaces |

1. Read `sop/themes/catalog.tsv` for id → `group` + `paletteKey` + catalog md.
2. Import `sop/themes/<group>/{web,ui,erp,token}-palettes.mjs` as needed.
3. Keep `catalog/<Family>.md` as the aesthetic brief (do not discard meaning).
4. Prefer the closed WorldMan **web** primary names above for shared components;
   map other sets onto CSS variables with a clear prefix (`--ui-*`, `--erp-*`,
   `--tok-*`) so they do not collide.

Preview all four scenes: open `sop/themes/index.html` via a local static server.

Color values are typically `hsl(...)` strings. Normalize in the theme loader if
needed. Semantic fg/bg pairs are contrast-checked (≥ 4.5:1) at pack build time
(`tools/check-theme-contrast.mjs`). Country packs cover **zfr L2 + L3**
(Tier I–III); see `catalog.tsv` `locales` and `ELEMENTS.md`.

## Secondary / mid tones

Do **not** invent a second naming scheme. Optional secondary tokens may be
**generated** when omitted — adjust lightness / saturation from the primaries
(same craft spirit as minor-themes mid-tones, but for web roles), e.g. `muted`,
`secondary`, `popover`, `input-background`, `sidebar*`, `app-canvas`, and
status `*-foreground` pairs.

## Apply + switcher

1. Implement `applyTheme(id)` / optional `previewTheme(id)`:
   - set `--${key}` on `document.documentElement`
   - set `dataset.theme`; toggle `.dark` when `type === "dark"`
   - persist id in `localStorage`
   - call once at boot before first paint when practical
2. Add a **visible** theme control in app chrome (settings / header / footer).
   Group by `minor` / `vibe` / `country` (or catalog family).
3. Default: a light soft theme (e.g. `innocent`) or the closest match to the
   Figma look; note non-obvious choices in `sop/TODO.md`.

Preserve layout and interaction; theming changes color through tokens only.
